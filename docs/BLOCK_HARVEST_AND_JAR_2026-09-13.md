# 方块挖掘、掉落与兼容测试包

## 原因与修改

这次使用真实注册表和 Block.getDrops 复现：2,205 个没有专用 getDrops 的可掉落方块，全部缺失默认掉落。修复前清单见 block-loot-before.json。这不是纯贴图问题。

新增 BlockLootPack 内置服务器数据包，为已注册 GT 方块提供标准掉落表，默认一块掉一个自身物品，使用 survives_explosion 条件。无物品形式的方块和流体方块不生成物品掉落。走专用 getDrops 的矿石、岩石、材质块和带 NBT 机器继续使用各自逻辑，不叠加第二份方块。数据包优先级在底部，数据包仍可覆盖默认表，不写入几千个零碎资源文件。

新增 BlockHarvestPolicy，统一给全部非流体 GT 方块提供挖掘分类。依据 GT6 Loader_MultiTileEntities 的 aMetal/aMachine/aMetalWires/aWooden/aStone 等分类：材质块/石材用镐，木制外壳和木箱用斧，粉块用铲，机器和金属管轴支持扳手，导线支持剪线钳，树叶支持剪刀。其余普通方块按既有材质声音分类；工具操作与拆卸是不同动作，右键调整功能没有改成左键挖掘。

- Forge 原生 mineable 与 needs_* 标签接入全部注册表；GT 扳手和剪线钳通过工具判断与 Forge harvest 钩子接入。
- 材料方块、石材和矿石移除“任意镐无视等级”捷径，挖掘速度回到正常工具/硬度计算。矿石要求合适工具；基岩宿主矿保持不可破坏。
- 超过原版三种 needs_* 标签的 GT 材料等级仍检查实际工具等级，不能用木镐绕过。
- 保留材料定义中的硬度、抗爆值及已有特殊掉落，没有把所有机器粗暴改成同一个硬度。
- 树叶改为原版思路的概率树苗，剪刀/精准采集掉树叶；柳/蓝桃花心补树枝概率。当前树种体系尚非完整原版生态，这不是生态全集移植。
- 桶/罐按原版 TileEntityBase08Barrel.writeItemNBT2 保存流体和状态到 BlockEntityTag；破坏不再同时向邻居排出同一份流体，重放读取保存内容。
- 现有箱子独立内容物掉落、Mass Storage 打包和机器待产物 NBT 路径保留。

## 验证

新增测试覆盖默认掉落全注册表、每个非流体方块的挖掘标签、真实生存玩家拆轴只掉一件、材料等级、木桶用斧、剪线钳识别，以及桶拆卸/放回的流体守恒。最终结果和 JAR 信息见下方追加记录。

本轮不宣称所有方块的每一项原版硬度数值、所有爆炸故障和附魔特例都已经逐个等价验证；本次落实的是全注册表默认掉落缺口、挖掘分类/等级及已确认的容器掉落问题。仍需真实客户端和第三方模组测试。

## 兼容测试建议

使用 Minecraft 1.20.1 Forge、Java 17；本项目开发 Forge 为 47.4.20。将本次正式重混淆 JAR 放入测试实例 mods，移除该实例中旧的同 modid JAR，避免重复加载。JEI/Jade 使用对应 1.20.1 Forge 版本。

1. 生存模式测试轴、管、导线、手工工具方块、箱子、木桶、反应堆墙和多方块主控。创造模式本来就不正常掉方块，不能用创造破坏判定掉落修复失败。
2. 镐/斧/铲/扳手/剪线钳分别对适用方块测试，确认工具速度与掉落。高等级材料用对应等级工具。
3. 箱子存物后拆除：方块一份、内容一份；Mass Storage 重放检查数量；桶注水后拆除重放检查数量。
4. 与其他模组一起测试同材质 Tag 配方替代、JEI 和 Jade、第三方工具挖掘。不同模组专用扳手的交互协议并不自动等价于 GT 扳手。
5. 出错保存 latest.log、崩溃报告、方块 ID、工具 ID、朝向和复现步骤。测试旧世界前保留副本。

## 红色合金线补充核对

指出希望每格衰减 1、最大值 16；但所提供的 GT6 源码 Loader_MultiTileEntities.java 第 1895–1896 行设置 NBT_PIPELOSS=MAX_RANGE/16，MultiTileEntityWireRedstoneInsulated.getRedstoneAtSide 将输入乘 MAX_RANGE 并扣损耗，输出用 bind4 限定为 0–15。该源码对应约每 16 格衰减一级，和描述不同；未经确认不把自定义行为标为原版修复。当前待确认选择。
