## 3. 主要发现：先修哪些

### A. 可能影响进游戏或配方同步

工具装配配方的网络写入只发送一个 UTF 字符串，读取还额外读取 VarInt；已用源码及现有字节码确认不对称。另一处打火工具配方会反序列化成普通工具配方，丢失专用匹配逻辑。现有服务端配方测试没有覆盖网络往返。

这是下一阶段第一优先项。验收必须包含连续两条配方的读写、无越界/残余字节，以及真实客户端登录，不能只看编译通过。

### B. 库存、掉落、保存与自动化

记录了漏斗部分拾取时丢弃剩余物品、满背包树洞采集的重复产物路径、饮用后容器返还、树液袋保存/破坏掉落、战利品容器重复生成等问题。具体触发条件与源码证据在主报告的第 13–14、22、61、69、101 项。

USB 交换器的玩家操作把硬盘固定放到目标槽，导致源硬盘路径不可达；部分库存 capability 每次查询都新建且没有失效处理。物品管和覆盖板过滤之间也存在绕过或交互顺序问题。现有测试中有直接写库存的情况，没有走玩家真实点击路径。

这些问题中，源码可确定的错误与仍需游戏内确认的影响已分别写清，未把所有推测都称作已复现的复制漏洞。

### C. 生存配方和能源计算

多组配方只在服务器启动时插入，资源重载后会丢失。还发现炉炼倍率重复应用、四联/九联管消耗、矿石与小矿掉落/围岩处理、能源网络遍历和接受量计算、并行加工工作量等差异。

另确认部分原版内容仍是简化行为或缺口，例如工具细节、蜂群行为、世界生成分布、容器和多方块主控。已有注册数量不能代替这些行为已还原。

### D. 最容易把已有成果弄坏的生成器

这部分做了多轮独立副本复现，正式文件未被覆盖：

- 材料注册相关生成过程会丢掉当前手工补充的别名/显示名。
- 多物品生成过程会丢失 320 个扫描蜜蜂变体及相关资源。
- 前缀资源生成器会从中英文语言文件中各净删除 2,539 个键，并改写 160 个中文值。
- 旧书架脚本会将正确贴图引用改回不存在的路径，重新带来紫黑贴图。
- 旧提示页脚本会重复声明 DidYouKnow 字段；另一个提示脚本会撤销锌流体 token 和染料数量修复。
- 多方块配方生成器会重新加入已删除的三种单方块机器目标。
- 部分组件和木管配方从空目录生成时缺少当前已有的镜像标记，不能省略后处理。

因此不能直接把历史脚本全部重跑一次。下一阶段需要先明确生成器负责哪些文件/键，把后补修复写回对应生成源。

### E. 测试和审计工具自身也有盲区

发现恒真断言、只检查数量不检查语义、只判断文件存在、打印错误却仍返回成功、把历史日志当新门禁，以及文本扫描误报等情况。

例如：前缀条件工具有 21 项跨到后一个声明取条件，且有 93 个共有前缀没有解析出移植版条件；它输出零缺失不能证明条件完全一致。注册清单只拿单方块表比对多方块，会误报已有内容缺失。方块配方抽取器默认查询 Storage 返回 0 条，包含匹配则返回 28 条。

主报告编号 0–138 是问题、差异和检查边界的索引，**不能简单宣称发现了 139 个独立且已运行复现的游戏 bug**；其中有更正、撤回或同一类问题的不同表现。
