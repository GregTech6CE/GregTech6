# 更新日志内容准则

本文定义 GT6CE 更新日志的收录范围、分类标准与条目编写原则（排版与链接写法见[格式规范](format-guidelines.md)）。

## 收录范围与版本归属

- **基线范围**：仅记录自 **2026-10-26** 仓库重置后合入 `master` 分支的变更；早于重置的提交、历史 PR（`#1`–`#136`）及历史 issue（`#1`–`#126`）均不计入更新日志或引用链接。
- **版本归属**：各版本内容严格按相邻 tag 之间的实际提交区间（`prev_tag..tag`）核对归属，不以 GitHub Release 文本中的错列或跨版本描述为准。
- **排除项**：纯内部代码重构（如 Stonecutter `//?` 清理、格式化、注释整理）、纯文档与测试补充、未改变产物或玩法的构建/CI 脚本微调不写入更新日志；涉及安装包显著瘦身或影响外部工具链的改动除外。

## 分类规范

下述“变更”统一包含新增、移除、迁出与整体重构，命中优先级为 **主要内容 > 次要内容 > 错误修复与平衡改进**（待 `rfc/roadmap-v1.0` 合入后由 `docs/roadmap/README.md` 统一承接本定义）。

### 主要内容（Major Changes）

- **系统变更**：完整玩法/功能系统或成套产线变更（如高分子产线、营养与硬币系统）。
- **破坏性变更**：打破现有存档、配置、数据包、资源包或外部接口向后兼容性的变更（如不保留旧 ID 的注册项与前缀移除、配置或脚本接口的破坏性调整）。
- **底层框架与全局规则**：材料、配方、多方块、网络、渲染与资源打包架构变更，或全维度世界生成与旧存档迁移规则变更（如连续地层重构、资源虚拟化）。
- **API 与扩展契约**：`Addon API`、KubeJS 对外契约与双端底层数据接口变更（如 `Addon API 1.x` 发布、双端组件语义收敛）。

### 次要内容（Minor Changes）

- **独立内容变更**：不构成整套系统的单个或少量材料、物品、工具、方块、流体及分支配方变更（如虚空收集漏斗、精工宝石采矿工具）。
- **交互、配置与展示**：配置项、局部方块/工具交互、引导提示、GUI 或 JEI/EMI/Jade 展示变更（如流体槽交互、EMI 查询页）。
- **工具链与局部性能**：调试工具、网络缓存调度、渲染剔除与构建环境变更（如离线地质调试、管道路由缓存）。

### 错误修复与平衡改进（Bug Fixes and Balance Improvements）

- **缺陷修复**：崩溃、并发异常、状态/掉落丢失、同步/碰撞箱/渲染错乱或本地化缺失（如渲染线程崩溃、硬编码文本漏译）。
- **既有设定补全**：补全已有系统缺失配方、恢复 GT6 既有行为、修正材料属性与标签归并（如反应堆缺失配方、标签补齐）。
- **数值平衡**：不改变核心机制，仅调整消耗、产出、概率、容量、耐久、温度门槛或生成权重（如 9 合 1 小粉合成、全防服耐久上调）。

## 编写原则

- **面向用户、简明扼要**：用自然流畅的语言概括实际体验、玩法、配置或平衡变化，每条控制在 1–2 句内，避免堆砌内部类名与琐碎实现细节。
- **单一主题**：每条只描述同一项变动或同一组直接相关的问题修复，严禁将不相关的改动拼合在同一列表项中。
- **Addon API 升级单列**：公开 Addon API 或扩展契约的版本升级，直接在 `主要内容`（`Major Changes`）中拆出独立条目说明版本号与核心能力，不附注在其他功能条目末尾，也不另设 API 专节子标题。
- **内容全记、修复精选**：玩法、系统、机制、配方、材料、世界生成、配置项及公开 API 的变更均需记录；错误修复与平衡改进精选收敛，优先保留对应已关闭 issue 的修复及影响面较大的关键改动，合并同源小步修改、略去琐碎微调。
