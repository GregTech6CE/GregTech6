# 跨版本统一方针

返回[跨版本要求与入口](../versions.md)。本文规定共享代码与两个节点（`1.20.1-forge`、`1.21.1-neoforge`）之间差异的裁决顺序、统一目标和例外条件。

## 适用范围

适用于共享输入与节点源码之间的所有版本分叉，包括 `//?` 分支、节点包装类、重复注册、列表/类型分叉、同名异义实现和初始化顺序差异。

## 历史前提

仓库经历 1.7.10 → 1.20 → 1.21 迁移。迁移过程中产生了大量未声明来源的版本分叉；它们不是 parity 决策，默认按待清理的遗留处理。只有 parity 文档、原版 GT6 或本文的例外条款能证明其保留理由。

## 权威顺序

1. [`docs/decisions/parity/`](../../decisions/parity/README.md) 中已审阅的 parity 声明；
2. 原版 GT6 golden 实现；
3. `1.21.1-neoforge` 实现（当前主要 playtest 环境与实现参考）；
4. `1.20.1-forge` 实现（低优先级；不作为行为基准，按上报修复）。

## 统一目标

- 每个内容家族只保留一条共享注册/访问路径。
- 尽量消除 `//?` 分支、节点包装类、重复注册和同名异义类型。
- `1.20.1-forge` 的独立实现只有在符合“例外”时才保留；否则迁移到 `1.21.1-neoforge` 共享路径并删除旧路径。
- 不为了保留两版差异新增共享谓词、静态列表或转发层。

## 落点偏差

同一内容家族在两个版本中实现落点不同，属于待清理的遗留，不是平台 API 例外，也不是 parity：

- 注册归属、holder 类型、节点目录、复合目录、菜单落点；
- 物品类依赖、节点包装类、静态谓词；
- 创造栏等内容装配；
- 空块、同义分支、拆分重复。

节点专属的旧存档迁移类不属于落点偏差：它只在生成该存档的节点上有意义，另一个节点不会产生或加载这类数据。保留节点实现，并在类或注册处写明迁移范围；不要为了消除分支把它移入共享源码集。

处理措施：

- 每个内容家族只保留一条共享注册/访问路径；
- 删除 `1.20.1-forge` 的旧路径，不只改调用点；
- 不新增共享谓词、静态列表或转发层来保留差异；
- 保留 `//?` 前先排除自身注册顺序、初始化顺序、缓存、包装层、重复注册和条件编译组合。

具体案例见[实现落点偏差](Placement/README.md)。

## 行为容忍

- 允许统一导致 `1.20.1-forge` 行为变更；行为基准是 parity 声明与原版 GT6 golden，`1.21.1-neoforge` 是当前实现参考和主要 playtest 环境。
- 不追求 `1.20.1-forge` 的边界行为一致；落不准时参考 parity 文档或 golden 实现。
- `1.20.1-forge` 的编译是 CI 门禁；基本启动按人工 `runServer` 验证。深度 playtest 以 `1.21.1-neoforge` 为主，`1.20.1-forge` 问题按上报修复。
- 相对于 golden 的行为变更必须记录到 parity/decision 文档；结构变更记录到架构文档或提交说明。

## 例外：平台 API 差异

只有同时满足以下条件才保留 `//?`：

1. 差异来自加载器/游戏版本的 API 运行时行为（类/方法不存在、签名、注册表、能力、网络、事件生命周期）；
2. 无法通过共享门面吸收；或吸收需要新增跨版本谓词、静态列表或转发层，成本明显高于保留最小分支；
3. 已排除我们自己的注册顺序、初始化顺序、缓存、包装层、重复注册、条件编译组合导致的差异；
4. 分支处写明原因、影响面和验证方式。

不满足上述条件的差异按遗留处理：统一到 `1.21.1-neoforge` 路径并删除 `1.20.1-forge` 路径。

## 决策流程

对每个候选分支：

1. parity 文档是否声明？→ 保留，按 parity 处理。
2. 是否与原版 GT6 golden 一致？→ 以 golden 为准。
3. 是否是平台 API 运行时差异？→ 按“例外”证明并保留最小分支；否则进入 4。
4. 是否为重复注册、陈旧包装、列表分叉或同义实现？→ 统一到 `1.21.1-neoforge` 共享路径，删除 `1.20.1-forge` 路径。
5. 行为是否相较于 golden（或 parity 声明）变化？→ 记录；必要时补 parity/decision 文档。

## 反模式

- 用共享门面把两套注册路径包起来，分支仍在。
- 把 `1.20.1-forge` 的独立实现当成 parity，而不查 parity 文档或 golden。
- 为保留 `1.20.1-forge` 边界行为新增共享谓词、静态列表或转发层。
- 只改调用点、不删旧注册路径，导致双注册或死代码。
- 把平台 API 差异和自身逻辑差异混为一谈。

## 记录与验证

- 相对于 golden 的行为变更记录到 parity/decision 文档；注册路径、holder 类型、类删除等结构变更记录到架构文档或提交说明，不进入 parity。
- Stonecutter 文档只记录代码写法差异；行为差异的权威记录在 [`docs/decisions/parity/`](../../decisions/parity/README.md)，不在 Stonecutter 分类中重复。
- 两个节点 `stonecutterGenerate` + `compileJava` 通过。
- `spotlessCheck` 通过。
- 检查生成源码：分支折叠、import 残留、两节点一致性。
- 行为基准是 parity 声明与原版 GT6 golden；`1.21.1-neoforge` 是实现参考和主要 playtest 环境，`1.20.1-forge` 至少验证编译与启动，深度测试按上报安排。
