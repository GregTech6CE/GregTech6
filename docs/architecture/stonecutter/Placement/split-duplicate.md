# 拆分重复

## 子原因

同一个条件被拆成两个单侧块，非空体相同；或者同一注册项在两个版本各写一遍。

## 例子

### 修复前（拆分重复）

```java
//? if >=1.21.1 {
methodA();
//?}

//? if >=1.21.1 {
methodA();
//?}
```

### 修复后（拆分重复）

```java
//? if >=1.21.1 {
methodA();
//?}
```

相关提交：`e15ae180`、`60bec479`。

### 修复前（重复注册）

同一注册项在两个版本各写一遍，或消费者各自分支取注册表。

### 修复后（重复注册）

能共享的注册表走 `ContentRegistrar`，只能节点注册的保留在节点实现。不要在两版各维护一份同一内容的注册列表。

### 为什么这么修复

拆分重复会让分支数量翻倍；重复注册会让两版内容逐渐漂移。收敛前先确认注册 ID 与顺序不变。

### 其他可能的修复方式

- 保留两份注册列表，用脚本同步。仍然需要人工核对差异。
- 把注册项移到 core 定义。只有确实与加载器无关时才可行。
