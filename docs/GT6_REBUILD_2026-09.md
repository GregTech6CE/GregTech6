# GT6 行为重做记录（2026-09-11）

本批重新核对 F3–F12，先处理公共工具交互、F10 手工台和 F11 箱子开合。这里的完成项不代表 F3–F12 全部完成，也不把注册数量当成功能完成度。没有使用 GTM 的实现代码或素材。

## 公共工具交互

- `api/tool/ToolInteractionTarget`：方块声明支持的工具操作。
- `api/tool/ToolInteractionSpec`：朝向属性、水平四向/六向策略、连接类型。
- `api/tool/ToolInteractions`：九宫格目标面、合法性检查、服务端修改、邻接端同步、工具消耗。
- `client/ToolFaceOverlay`、`SlabPlacementOverlayRenderer`：读取上述声明和检查结果，显示连接状态与目标区域。绿色表示当前可操作，红色表示不允许；没有额外的机器类型白名单。
- `MachineRotationType.handleWrench` 保留为旧调用入口，实际执行委托公共实现。

已经接入普通朝向机器、引擎、能源节点、两种漏斗、坩埚龙头、磨石、金属箱子、流体管、物品管、电线、轴。普通水平机器由共用基类声明策略，不需要每台机器复制点击逻辑。特殊方块可以覆盖声明并提供 `toolStateChanged` 回调，例如龙头同步其方块实体朝向。

对照依据：原版 `UT.Code.getSideWrenching`、`TileEntityBase09Connector.onToolClick2`。移除移植版擅自添加的“潜行清空全部连接”；潜行仍只操作目标面。修改连接时同步同类邻接端，检查轴的共轴限制。命中坐标先减去方块整数坐标，再转换为 float，避免远坐标选错面。

## F10：已替换的实现

原版依据为 `gregtech/tileentity/tools/MultiTileEntityMortar`、`MultiTileEntityGrindStone`、`MultiTileEntitySiftingTable`、`MultiTileEntityCrank`。

- 臼：空心内壁、底板与杵；独立 Mortar 配方表；手持原料直接加工。移除 `Mortar = Sharpening` 的错误别名。
- 磨石：底座、支腿、轴、可安装/耗尽的磨料；水平朝向；安装砂岩或相应材料后，手持物品操作十次。普通附魔物品可去魔并返还经验，排除 GT 工具、附魔书和诅咒物品，经验按原版减半向上取整。
- 筛台：恢复四角支腿和下层接料盘；保留输入和十二个输出槽；顶面启动后保持瞄准，每五 tick 推进一次，侧面取出产物；急迫/挖掘疲劳参与进度计算。输出概率不再强制全部成功。
- 曲柄：恢复贴面薄盘与连接轴尺寸、轴纹理。基础输入为负向 16 RU、每次一包，力量/虚弱影响转速，急迫影响包数。能源节点接受 RU 的符号并按绝对值计入缓存，避免负转速被直接拒绝。
- 模型底色与不染色的细节叠图分开；磨石物品预览显示未安装磨料的形态。`tools/rebuild_manual_models.py` 可重复生成这四组模型。

保留方块/物品注册 ID。旧手工台保存的 `gt.work` 仍可潜行空手取回；筛台新增输出槽和磨石磨料状态会保存到方块实体 NBT。

尚未宣称完成：全部材料/样式变体、配方查看按钮、筛料堆的原版动态显示、村民操作曲柄、曲柄持续转动与红石反馈、完整管道侧面库存接口。原有十二个 `simple(...)` 工具方块（混合碗、榨汁器等）仍有占位实现，不能算已经重做。

## F11：金属箱子

原版依据：`gregapi/block/multitileentity/example/MultiTileEntityChest`。

- 使用服务端开箱人数、方块事件、客户端盖子控制器同步多人开合；定期核对正在使用的菜单。
- 菜单关闭后减计数；离开距离或拆除箱子后菜单失效。上方实体方块阻挡开启。
- 箱体、盖子、锁扣采用原版 GT6 的 64×64 UV 布局和铰链坐标，保留彩色/原色两遍渲染。
- 世界与背包使用 `MetalChestVisuals` 的同一模型；物品使用共享自定义渲染器，避免把整张箱子展开图贴在立方体各面。
- 金属箱子也接入公共水平扳手调整。保险箱、储物柜等不因此自动算完成。

## F3：电力与通量活塞引擎（续作）

对照原版 `MultiTileEntityEngineElectric`、`MultiTileEntityEngineFlux` 的输入、逐 tick 转换、工具操作、NBT 和纹理面选择。此节仅描述这两个系列，不能视为整个 F3 完成。

- 新增不依赖世界的 `PistonEngineState` 与共用 `PistonEngineBlockEntity`。按输入能量保存缓存，取消错误的 EU/RF 直接按 1:1 存成 KU；额定第一档机型分别为 32 EU → 16 KU、128 RF → 16 KU。
- 背面唯一输入，正面唯一输出；每 tick 一包 KU，活塞往返产生正负符号。输出没有接收者也消耗本 tick 输入，避免无限积蓄后突发倾倒。
- 恢复 32 档功率，默认第 16 档；输入除以 16 向上取整，输出向下取整。螺丝刀调整功率，软锤停止/恢复输入；停止输入后剩余缓存仍继续工作。
- 缓存标称容量为额定输入的两倍，允许原版完整能量包跨过容量边界。旧 `kuEnergy` 按其实际存放的未转换输入迁移一次；新增功率、活塞相位和开关状态持久化。
- 通量引擎背面增加 Forge Energy 接收能力；模拟注入不改变缓存，旋转后缓存的旧面接口不能继续输入。GT 输入与 FE 输入共用存储。
- 电力过压强度按原版电压档位计算，沿用项目现有过压爆炸开关。原版独立的爆炸/仅破坏配置组合尚未全量移植。
- 修正公共能源入口：调用机器自身侧面判断，防止不支持的面在低压路径吞掉能量包；拒绝无效包数与不可取绝对值的 long 最小值。
- 模型端板纹理按前/后/侧面分配，去掉顶底面错误使用前后纹理的问题。核心颜色随功率从蓝到绿到红，客户端收到档位更新后重建方块显示；保留不染色叠图。
- Jade 与物品说明显示实际功率和 EU/RF 输入缓存，删除虚构的额外能源输出和 KU 缓存说明。工具消息补充中英文。

验证：`PistonEngineContracts` 覆盖转换比例、全部 32 档取整、往返符号、停止输入后运行、模拟无副作用、整包跨容量边界、过压档位、颜色端点和公共侧面分发。17 项 Python 检查通过，92 个关联资源文件无缺失引用。完整 Forge 客户端画面、外部 FE 模组接线及重载档位颜色仍需游戏内验收。

尚未完成：全部原版注册变体核对、覆盖板/红石开关集成、原版完整故障配置、多人场景与世界/物品六向视觉验收。

续作构建结果：完整 `gradlew.bat build --offline --console=plain` 成功；工具消息单位调整后再次完整构建成功。已核对最终 JAR 包含新的活塞状态/实体类、修正后的两种引擎端板纹理映射和中文状态消息。
