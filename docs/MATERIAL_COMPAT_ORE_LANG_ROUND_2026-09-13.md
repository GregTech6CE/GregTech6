# 材料互通、矿处理、锅炉仪表和本地化修正

## 材料标签与严格绑定

按 Forge 1.20.1 的 `forge:类别/材料` 约定实现，如 `forge:ingots/iron`、`forge:dusts/redstone`、`forge:raw_materials/copper`；同时生成类别父标签和 GT 专属形态标签。常用形态包括锭、粒、粉、小堆粉、小撮粉、宝石、板、杆、长杆、齿轮、环、螺栓、螺丝、箔、粗矿；普通矿石与适合的储存块还具有物品 / 方块标签。小矿石、板制储存块、工具等不会混入普通纯材料标签。

- `MaterialTagPack` 从真实注册表生成内置数据包，所有标签 `replace=false`。标签经正常数据包加载和服务端同步，可被其他模组配方使用。没有将上万份 JSON 写进 resources，因此不会因此增加 processResources 的小文件复制负担。
- `MaterialEquivalence` 统一材料 + 形态 + 单件含量识别。铜、铁、金锭和红石粉等原版物品与对应 GT 形态双向匹配。机器选配方、砧 / 工具方块的插入检查、工具装配均接入。
- 标签只按具体形态匹配，不使用 `forge:ingots` 这种总类判断同一种材料；一份小撮粉不能当一份粉，九份压缩粗矿也不能当一份粗矿。
- 常见拼写 aluminium/aluminum、sulfur/sulphur、quartz/nether_quartz 有兼容别名。
- 具体物品配方优先于材料替代，保留专属配方行为。跨物品替代不吞带 NBT 的特殊物品。
- 不删除现有物品 ID，不强行转换玩家库存。标签互认不等于物品 ID 合并。
- 原版木棍可以参与 GT 工具头 + 工具柄装配，无序配方 Tooltip 索引支持原版材料形态。

官方依据：[Forge 1.20.1 Tags](https://docs.minecraftforge.net/en/1.20.1/resources/server/tags/)。本项目是 Forge 1.20.1，因此以该版本的 forge 标签约定为主，没有误用新版迁移后的 c 命名空间。另对照本地 GTM 的小堆粉 / 小撮粉标签名称，没有复制其实现代码。

## 炼药锅为什么错误地得到三氧化二铁

原移植把两个独立的 GT6 字段合并使用：

- `mTargetCrushing`：矿石破碎目标，原版铁设置为 Fe2O3。
- `mTargetPulver`：普通材料粉碎目标，默认仍是自身。

原版炼药锅由 `LoaderItemData` 明确设为七单位铁；原版 `RecipeMapShredder` 读取 mTargetPulver。因此它应当回收七份铁粉。现在已拆分模型字段，普通回收改读 pulver，并恢复原版 MT 中 12 条显式 setPulver 定义。回归测试检查炼药锅回收结果以及铁的两个目标确实不同。

## 矿处理

- 普通矿石 / 粗矿使用目标材料、目标比例和矿物倍率。破碎机有两份保证主产物；锤子有一份，耗时按原版产量和质量计算。
- 不再给普通粗矿套用仅适合 DUST_ORE 的筛选配方。
- Minecraft 普通 / 深层矿石，以及粗铁、粗铜、粗金及其储存块显式接入，补上下界金矿与石英矿。
- 岩块不再乘上错误的“完整矿石 × 倍率 × 4”公式；按岩块 9/4 单位生成粉末回收。
- 小矿石改为 `Drops_SmallOre` 的位置种子加权掉落，包含宝石等级、粉碎矿、时运和精准采集权重以及部分宿主粉末。精准采集也不返回原矿方块，符合该原版行为。
- 移除虚构的小矿石半产量破碎配方，原版对应机器分支本身标记 TODO。
- 油砂离心原本把原油放在输入位置且砂粉数量少乘了单位常量；改为两单位油砂产出 500 mB 原油和四份砂粉、128 ticks，不消耗原油。

**仍需继续核对**：不同宿主岩的完整破碎副产物、特殊矿的额外概率产物、完整洗矿链和所有第三方矿物映射，尚未宣称逐条等同原版。小矿石宿主材质能否找到对应粉末也取决于当前宿主材料映射。

## 锅炉仪表

统一底图和指针 UV，修正从北面观看时的水平 / 竖直映射；法线随模型朝向矩阵变换；从锅炉前方方块采样光照，不采样不透光锅炉内部。使用适合方块实体贴图的渲染类型。

这部分通过编译并检查了资源与坐标，尚未用图形客户端确认最终画面。建议在明亮地面朝东南西北各放一台，检查空锅炉与升压后的指针方向和亮度。

- 中文源改为提供的 `F:/Dev/GregTech6/GregTech.lang`，恢复导入 1,065 个材料译名。
- 运行时审计实际注册物品名称、流体展示物品名称、材料名称及其嵌套翻译参数，发现并补齐中英文各 587 个缺失名称键。
- 补齐先前 91 个中英文不对齐键，以及锅炉 Jade 缺失状态提示。当前 en_us / zh_cn 各 8,324 键、180 个 tooltip 键。
- 所有实际注册名称审计缺键为 0；109 个静态提示键检查缺键为 0；中英文占位符数量一致。
- 原版纯材料与 GT 对应形态共享材料 Tooltip；高级提示增加具体兼容标签，并区分材料粉碎与矿石破碎目标。
- 保留已实现的化学式、燃料、可燃性、工具质量 / 速度 / 耐久、含量、熔沸点、重量、材料来源、无序配方数量信息。
- 已补齐当前系统的名称和已调用提示键，**不等于已经实现 GT6 所有 Tooltip 行为**。未移植的放射性 / 毒性等材料标记、部分特殊机器操作描述，不能只填文本就算实现；本轮没有虚构这些数值或宣称行为全量等同。

## 原版材料是否从合成表推测

核心材料由 MT / OreDictMaterial 显式定义；OP 定义形态、单位和生成条件；OreDictionary 把各模组物品关联到材料与形态；LoaderItemData 明确登记原版及兼容物品的组成。

部分带 reversible 标志的 GT 合成注册，确实会汇总输入的 OreDictItemData 写入产物。可参见原版 CR.shaped 的 aReversible 分支。它不是扫描所有合成表来推测所有材料，更不是通过合成表推测元素、熔点、密度等物性。

移植上一轮的现代合成推导只是给原版没有的新物品补参考组成，仍限制自动回收；它与 GT6 核心材料显式注册不是一回事。
