# manual-ingame：游戏内人工验收

## 验证方式

游戏内验收覆盖自动检查无法证明的行为：世界状态、机器 tick、交互权限、渲染、Mixin 注入、网络同步、可选集成和存档迁移。它不替代 JUnit、GameTest 或编译，而是在这些检查之外确认玩家实际看到和操作到的行为。

修改世界、方块实体、机器 tick、交互、渲染、Mixin、网络、配置或可选集成，或 package 文档的验收章节要求游戏内确认时执行。纯文档改动不启动游戏；只运行一个平台不能推出另一个平台行为相同。

只选择与改动相关的场景，至少考虑：

- 无输入、资源不足、输出阻塞、能量或流体不足。
- 方向变化、拆装、区块卸载与重载、存档保存与读取。
- 客户端与专用服务端分别启动；专用服务端不加载客户端类型。
- 可选集成：未安装目标模组与安装匹配版本两组启动。
- 资源包重载、GUI 缩放、JEI/EMI 显示与快捷键。

具体到机器、配方、流体、能源、网络与可选集成的勾选项写在对应 package 文档的验收章节里。

## 验证原理

### 矿物处理展示页

生产页已连接 `MaterialProcessSnapshot`，JEI 与 EMI 复用展示模型和面板。两者都从 viewer 最终可见的工作台、机器与第三方配方构造材料行；权威快照补充 `viewer(false)` GT 机器配方、原生单位／概率和活动世界生成。

JEI 与 EMI 数据源分别核对：工作台压块／拆块、熔炉、已安装机器和第三方加工都进入各自材料页；GT machine row 不重复；`viewer(false)` 的切割机、真空冷冻机、组装机、CNC 与坩埚合金化等在两页均存在。包含空网格的有序合成进入加工图；没有实际输入的行不能成为加工来源。通用标签／候选浏览页不进入信息区；GT 材料单位输入说明仍可打开。GT 材料单位模板即使 `supportsRecipeTree=false` 仍保留原生材料单位与概率；工具装配和可读取的第三方非树加工进入图中并使用未确认关系。零数量工具只作为催化剂，不使整条配方降级。相同原配方 ID，以及同分类下仅槽位顺序或网格占位不同的等价加工行不重复；数量、概率、原生状态或工具不同的行继续保留。超过每侧 128 槽、512 步或 4096 条关联时，页面应显示相应正文中的截断提示。加入坏记录时应有诊断日志和覆盖提示，其余有效路线仍可查询。tag 的同材料候选保持一个 selector，候选集合不同的 selector 不得因首个图标相同而合并。隐藏、延迟注册、资源重载与重新入服后页面跟随当前 viewer 配方，旧导航失效。检索输入、工具及产物不按配方出现次数重复，首次打开才构建详情，仍须保留完整原生批量及概率。分别核对 JEI-only、EMI-only、双装和无 viewer 专用服务端。

1. 在 JEI／EMI 中打开真实材料的“矿物处理”。页面应直接显示同一张画布上有内容的来源／内部转换／回收／去向区域、区标题与相邻区域分割线，空区域不留占位；世界生成和泉进入来源区；无切换或分页。连续链水平向右，替代路线和分叉就近分行；未分类步骤、无外部入口环及自环不能消失。不同 GUI 缩放下右侧、底部裁剪正确。
2. 切割机三种润滑剂相同机器图标和完整可见输入或输出时只显示一条路线；仅首产物相同而其他可见产物不同、输入又不同的路线保持独立，全部原生步骤仍保留，辅料不生成图节点，通过右上角 `+` 和 tooltip 查看。EMI 物品和机器使用原生槽位，确认自定义来源／用途绑定、点击释放、R/U、收藏及拖动物品均与普通 EMI 槽位一致，不精确锁定原配方；JEI 沿用普通来源／用途 focus；EMI 使用原生 tooltip，JEI 常规 tooltip 只显示名称；`+` 区域只列合并配方数与辅料名。非 1 件产量、U／mB 和非必然概率在图标上可见，精度保留至原生百分比；确定的 1 件产出不加数量／概率角标，未知概率显示 `?%`。共享资源采用生产端口的量，多个变体的不同量显示多值／省略号并可悬停查看；时间、能量和 native guard 仍保存在原生配方。锤子加工应使用 EMI 同分类已有图标，其他工具／多方块类别也应一致。
3. 资源局部副本带 `↗`，回流带 `↩`。悬停只突出相同物品的全部实例，机器图标也按真实物品匹配；其他资源、机器和连线均不跟随高亮，移到空白清除。不同 NBT／组件状态分开，流体副本按完整显示身份匹配。查询目标持续显示淡绿色外框，移开鼠标后仍保留。每条配方有较浅外框，独立小配方容易区分，共享端口与网格不能使边框包住相邻机器。连接为单段直线，分支斜连，输入无箭头、输出有箭头；回流不占顶部通道，确认关系不因循环改为虚线。
4. 对带 NBT／组件物品与真实流体，逐个副本检查左／右击、R/U、tooltip 和 EMI ingredient provider；流体代理应查询实际流体。各节点使用实际显示的完整物品／流体状态查询，无法恢复时保留符号，不用无数据假栈。
5. 来源／内部转换／回收／去向决定横向分区，不依据机器名称分组；“本材料＋辅料 → 本材料其他形态＋副产物”仍属内部转换。工具、存在条件及额外辅料／副产物均不扩展生产路线。主材料的多输入、多输出分支仍保留。同机器图标下，完整共同可见输入加工成多个产物，以及完整可见产物相同的替代输入应折叠为三列网格；完整共同输入不同不能仅因其中一个原料相同就按输入折叠。不能将 A→X、A→Y、B→Y 连锁合并而暗示不存在的 B→X；工艺 ID、翻译标题和 method 等隐藏信息不应阻止相同可见路线折叠；机器图标的原生状态不同或缺少可靠图标时保持独立。网格共用一根输入或输出线；用多种木材产树皮的路线确认隐藏辅料、批量和概率不同不阻止折叠；本材料的次要产物必须参与完整输出集合比较，差异可在普通配方查询中查看。透镜或螺栓加工等本材料多输出按端口顺序紧邻排成至多三列网格，共用输出箭头；共享资源也不能把产物挤到其他配方之外。逐格验证原生查询、悬停和 EMI 命中；同一组矩形内部不能插入其他路线的节点或连线。通用研磨／熔化回收配方同时核对 GENERIC 归属及 Shredder／Melter／Smelter 配方表，砧敲碎等普通加工不得进入回收区或被从材料来源中隐藏；回收途径在内部转换后、去向前的独立回收区展示，不能因产出少量粉末就铺成粉末来源；显式来源配方仍应存在。
6. 独立路线应紧凑排列成多列，局部副本不在远处预留依赖列，短配方也不被其他路线的宽网格撑开。分别查询原料、粉末、锭、零件与真实流体，材料总览只匹配页面所属材料，不能因另一材料配方使用了该物品作辅料、催化剂或外来副产物而出现。每次查询打开与复位均为 100%，查询的具体物品／流体节点位于视口中心；无目标时定位代表链。先平移、缩放再查询另一形态及同一形态，确认缓存视图也会重新定位；不同 NBT／组件状态分别确认。滚轮围绕鼠标缩放，顶部 `−／+` 缩放；空白处左右、上下拖动有效。在 100%、25% 和约 8% 比例下确认线宽、虚线间距及箭头与图标同比缩小，不出现盖住整图的固定尺寸箭头。缩放和平移后，图标、`+`、tooltip、点击及 EMI 悬停命中一致。 调整窗口尺寸及 GUI 缩放后，视口、按钮、裁剪与原生命中应一起变化；右上角全屏按钮展开到窗口，Esc 或按钮返回原查看器。全屏、返回及窗口变化均保留中心世界坐标和缩放；验证全屏中的 JEI／EMI 来源／用途、快捷键、收藏及拖拽，流体仍查询真实流体。
7. 连续重载两次后确认配方增删同步、旧引用拒绝跳转；断线／换服不沿用回调。布局副本数不改变配方数量或原生 viewer 索引；方法标签只来自 API target／reagent 声明。
8. 两平台分别检查 JEI-only、EMI-only 和双装环境，双装沿既有去重规则。另验无 viewer 的专用服务端与独立远程客户端；未实际执行的场景不能用编译或集成服务器静态表代替。

材料展示页不再维护逐布局场景的示例 GameTest。原状态、辅料隐藏、路线折叠、连续链、循环、副本、排布和关联保留必须直接按上述步骤做真实查看器验收；core 的图测试只证明纯数据与查询预算，不证明投影布局或鼠标手感。

## 注意事项

- 使用隔离实例；EULA 由操作者自行处理；完整日志、截图与实例配置放 `work/<任务名>/`，公共记录只保留脱敏结论。
- 记录提交或源码状态、JDK、Minecraft 与加载器版本、GT6CE 构建、依赖模组及版本、配置差异。
- 每条场景写清前置条件与操作、预期、实际、判定和平台；判定使用“未验证 / 部分验证 / 验证通过 / 已知失败”。
- 结束时分别列出“执行且通过”“执行但失败或阻塞”“尚未执行”，不要由一个平台启动成功推出两个平台行为相同。
- 不用人工观察替代本可自动化的规则；能在 JUnit 或 GameTest 中覆盖的行为优先补自动测试。
- 不把编译成功、客户端画面正常或单个平台启动写成完整验收。
- 不通过关闭 Mixin、放宽权限或跳过可选集成启动来获得“通过”。

## 运行命令

运行客户端与专用服务端：

```bash
./gradlew :minecraft:1.20.1-forge:runClient
./gradlew :minecraft:1.21.1-neoforge:runClient
./gradlew :minecraft:1.20.1-forge:runServer -PserverDirectory=../../../work/server-forge
./gradlew :minecraft:1.21.1-neoforge:runServer -PserverDirectory=../../../work/server-neoforge
```

Forge 默认实例在节点内 `run/`，NeoForge 客户端/服务端在 `run-client/`、`run-server/`。都属于本机数据，不提交存档或配置。

`-PserverDirectory` 由 Gradle 按节点项目目录解析；要放到仓库根 `work/` 时使用上面的 `../../../work/...`。

可选集成开关：`-PkubejsRuntime=true`、`-PcompatRuntime=ie|mek|ae|pr|hc`（每次选择一个值）、`-PemiSmoke=true`、`-PemiOnlySmoke=true`。具体依赖见 [Forge 配置](../../../../gradle/platform-forge.gradle)与 [NeoForge 配置](../../../../gradle/platform-neoforge.gradle)；加载依赖不代表集成已通过验证。

`-PdirectCoreClasspath=true`、`-PdirectCoreResources=true` 是本地运行优化；常规打包验收保持默认配置。`directCoreResources` 跳过 core 的 `processResources`，贴图以源码原样加载，`iCCP`、`pHYs` 等元数据块仍然存在，`IDAT` 块过滤也不生效：本地看到的画面不能代表发行包，资源相关验收仍需按默认配置重新打包一次。

修改 GUI 模板、别名、图标引用或 PNG 时，先做静态预览：

```bash
python tools/gui/preview.py
python tools/gui/preview.py --output work/gui-preview
```

依赖、参数、输出与预览边界见[工具说明](../../../../tools/gui/README.md)。
