# 08：材料标签、形态、来源与处理图 API

本计划将独立的材料相关系统通过查询与投影纳入材料 API，保持主材料对象简洁。状态：部分实施；A（定义视图与 metadata）已完成，B 的 tag／替代组定义与查询已随 02 完成，常见形态的生产消费者迁移随 03 完成；C 的定义期规则、实际 item／block／fluid 绑定和 tag 桥接声明已随 03 完成，外部 tag 导入候选已随 04 接入统一裁决；D—E 待实施。接口与语义权威见[设计提议 0001](../../decisions/0001-material-data-api.md)，本页只维护实施顺序与独立验收。

08 是贯穿原计划的集成工作，不是在 07 后重做材料系统。A 在 01 的调查基础上、02 的接口定稿前完成；B 并入 02／03，C 并入 03／04，D 随 05／06 的有效结果发布，E 在 D 后实施；最终由 07 联合验收。

## 当前入口与前置事实

- 现有 `GregTechMaterials` 已有只读材料句柄；优先增加视图和适配，不向 `GTMaterial` 追加来源列表。
- `AddonMaterialContributor` 已覆盖材料、prefix、form、组成、熔炼和世界生成声明；追加能力使用默认方法和侧向 metadata 声明，不复制 SPI。
- tag 需分别盘点 `MaterialProperty`、`MaterialRoleFlags`、`MaterialGroups`、`MaterialTagAliases`、`MaterialEquivalence` 和 `MaterialTagPack`。
- 加工来自实际 `RecipeMap`、`RecipeManager` 和动态／unit 提供者；`allRecipes()` 不是可无成本反复读取的完整静态表。
- 世界生成来源先追踪活动矿脉、小矿、岩层及 `WorldgenInfoData`；EMI 当前也从该 JEI 包中的数据入口取信息。
- 用户截图作为处理图信息组织目标；不把截图的具体图标连接当作待硬编码的配方表。

## A：确定薄视图与最小公共契约

状态：已实施。API 1.5 提供 `MaterialKey`、`DataKey`、`FormKey`、类型化 `PropertyKey`／`MaterialProcessKey`、不可变 `MaterialView`、`MaterialCatalogView`、metadata SPI 和可扩展 process view；游戏侧内容快照仍属于后续 C—E。

### 步骤

1. 在 01 的清单上标明 tag 的四种语义、每个 form 的规则与注册结果、每类加工关系的实际所有者。
2. 先只定义稳定材料引用、现有 form 引用、扩展 key、类型化属性与不可变视图；编写纯消费者样例，确认只依赖 API JAR。
3. 由 `GregTechMaterials` 新入口取得定义视图；游戏侧内容快照入口显式接受 server／level 上下文，公共模型不包含游戏类型。
4. 制定新服务未绑定、未就绪、旧宿主不支持、未知 key 和已过期引用的失败语义；不可统统返回空集合。
5. 选定公开类型位置和兼容策略后更新 API 版本说明、实际包职责与测试。实现前不把提议方法写进已支持 API 列表。

### 独立验收

检查集：D、F、J、A；接入平台入口后加 C。

- 仅 API JAR 的消费者能声明 metadata、读取视图签名；不借 core 或 main 输出。
- 同 key 异类型、内置 metadata 的可变值、非法引用均被拒绝；所有返回集合不可变。自定义 process value 保留扩展性，由 Javadoc 规定注册后不得动态修改，宿主不强制深度冻结。
- 旧的 `MaterialDeclaration` 构造／builder 和旧只读句柄消费者继续通过；既有宿主实现不会因增加抽象方法直接失效。
- 主材料视图没有配方表、矿脉列表、资源 tag 成员和 UI 坐标字段。

## B：材料分类、能力与替代组

状态：已实施本轮范围。规范目录中的分类和组在 READY 后发布为不可变查询；附属可声明自有 namespace 的 tag、tag 包含关系、替代组及组嵌套。未知引用、跨所有者冲突、tag 环和组环均拒绝发布。内置 `Any*` 工艺消费者已迁移到组键查询；旧 `MaterialGroups` 和 re-registration 访问器只保留弃用兼容。

### 步骤

1. 与 03 的 flag 迁移一起实现分类 tag 和替代组目录；现有 `Any*` 消费者按具体匹配语义迁移，保留必要的旧 re-registration 适配。
2. 为分类包含关系和组嵌套分别做未知引用／环校验。不能将组成员调用 `setRegistration()` 变成同一个真实材料。
3. 通过附属默认声明方法提交新 tag、group 和 metadata，核对 key 命名空间、跨附属同义声明和所有权。
4. 先迁一个有实际消费者的分类与一组替代匹配，再迁其余；无行为消费者的描述性 tag 保持纯查询用途。

### 独立验收

检查集：D、F、J、A、C；生产替代匹配发生变化时加 G。

- 打乱声明顺序，成员与诊断不变；循环包含、悬空材料和冲突声明失败。
- 为材料增加“金属分类”不会自动获得锭、燃料、回收或电解能力。
- Iron／Steel 可在经允许的组匹配中替代，但各自 ID、物性、组件与其他配方身份保持区分。
- 附属能增加自己的分类；未获权限不能改写 core 物性和加工能力。

## C：形态视图与资源 tag 桥接

状态：已实施本轮内容快照范围。当前 API 1.7 将定义期规则扩展为 item／block／fluid，发布运行期实际绑定并把显式统一物品纳入实际表示；规则资源与兼容资源保持区分。平台注册后发布内容快照与资源 tag 桥接声明，外部 tag 成员仍作为 04 的低优先级候选输入。

### 步骤

1. 以 03 的生成判定提供 form 规则视图，实际注册后构建可用表示索引；与 04 的完整成分及首选统一化目标接线。
2. 把材料 tag 拼写和 form 映射集中到桥接声明；逐项区分导出、导入和显式双向，不迁移无关技术标签的所有权。
3. 官方资源 tag 从已注册形态和权威成分导出；外部 tag 在加载后向 04 提交兜底候选，不反写生成规则或注册表。
4. 区分 item／block／fluid tag，同名路径也不混合；两个节点的目录格式与兼容 namespace 留在适配器。
5. 定义、注册绑定、tag 导入和成分裁决按固定阶段发布，拒绝查询尚未加载的临时结果作为永久事实。

### 独立验收

检查集：D、F、J、A、C、G；实际资源输出改变加 B。

- 可生成但未注册、有表示但无生产配方、规则禁止但保留兼容元数据等状态可区分。
- 复合工具头的主形态不覆盖完整成分；tag 导入不会按物品数量猜材料量。
- aluminium／aluminum 等已有兼容映射可查；普通材料分类不产生全材料全形态 tag 展开。
- 外部 tag 改动能更新候选和绑定，但不会在 reload 时创建／删除原生物品。
- 同一物品被不一致材料 tag 命中可定位冲突；高优先级显式成分不被覆盖。
- 两节点对共同材料与形态的语义一致，item／block／fluid 成员分别验证。

## D：来源与用途索引、快照发布

### 步骤

1. 先为最终静态机器配方建立输入／输出端口投影，保留共同输入、催化剂、单位、概率和原生状态限制；选合金与洗矿各一个闭环。
2. 接入 05、06 的已发布结果、数据包替换／删除与最终炉配方镜像，来源和用途共用同一索引。
3. 接入实际启用的世界生成；投影有效维度、高度与岩层，不从材料 `ORES` flag 推测世界里一定有矿。
4. 接入 unit 及首批动态族的符号投影，保留原生匹配引用和覆盖说明。不能调用全量枚举补齐每一种物品变体。
5. 盘点完整运行期回调，确定真正的发布时点；内容 generation 同时包含有效 tag、成分、配方与世界生成配置。原生对象不在后台读取中继续变化。
6. 提供有界来源／用途查询与原生引用解析，禁止跨快照引用混用；旧快照有界保留且保持自洽。
7. 检查现有客户端同步覆盖；复用已有事实同步，对缺失投影补充会话／generation 绑定。测试独立远程客户端路径，不依赖集成服务器共享内存。

### 独立验收

检查集：D、F、J、A、C、G；同步或可选 viewer 接线涉及实际交互时加 M。

| 场景 | 通过条件 |
| --- | --- |
| 洗矿副产物 | 索引输出端口的材料、批量、概率和洗涤输入与最终配方一致；无依据的主／副角色标未知 |
| 合金 | Copper 与 Tin 为同一步的共同输入，不能由单一原料推成无条件获取 Bronze |
| 电解／离心 | 产物与 06 一致，选择器不计消耗；未授权材料不凭组成获得来源 |
| 世界生成 | 关闭某矿脉／维度后相应来源撤下；高度使用生成器实际映射，权重不显示为掉落概率 |
| 化学组成 | 含某元素的矿物不直接被记作该元素的纯形态来源 |
| 动态规则 | unit 查询不展开全部物理行；不支持族返回部分覆盖及原因，空结果不伪称完整 |
| 原生状态 | 模具形状、损坏工具和容器等限制不丢失；同物品 ID 不代表同一可匹配资源 |
| 重载 | 删除／替换最终配方后来源与用途同步变化；重复两次无旧边累积；快照版本不混用 |
| 多世界／远程 | 不同 server／配置会话不共享来源缓存；断线／换服丢弃旧引用；远程图与服务器版本一致 |

## E：有界矿物处理图与消费者迁移

### 步骤

1. 在 core 对 D 的关系做有界前／反向查询，保留步骤节点和端口；处理循环、共同输入、分支与明确截断原因。
2. 建立材料矿物页：从实际 ore／raw／crushed 形态出发，主加工居中、副产物侧列，点击跳转原始配方或切换材料形态。
3. 先接入一个 viewer 验证交互，再让另一 viewer 复用同一图模型；颜色、坐标和图标在客户端适配。
4. `WorldgenInfoData` 的活动事实投影与原生图标构造分开，旧入口可暂时转发；材料来源不再要求 EMI 读取 JEI 的事实汇总类。
5. 清理被替代的来源列表和展示反推；保留完整性信息，未知工艺不画成无条件可执行的实线。

### 独立验收

检查集：D、F、J、A、C、G、M；新增客户端资源或交付产物时加 B。

- 合金／分解／回收形成环时查询终止；深度、节点和输出预算都生效，结果标明截断。
- 大 tag 或 unit 族的图大小不随全部候选笛卡尔积增长；至少用两档候选规模验证预算和索引复用。
- ore、crushed、dust、molten 与状态敏感子类型不错误合并；联合输入和随机副产物不丢失。
- 两 viewer 对同一快照导出的语义图一致，点击能定位对应原始步骤；显示图不反向生成配方。
- 无 JEI／EMI 的专用服务端可启动、查询并重载；未加载任何客户端／可选模组类。
- 两节点及远程客户端分别记录实际验证结果，不把纯图模型测试写成截图交互已通过。

## 交付顺序与完成条件

每个切片都能独立交付：A 的公共模型不要求先完成全图；B／C 的查询已有直接消费者；D 先有准确的来源列表，再由 E 绘图。每步保持旧 API 可用，迁移完一个消费者后再删除其重复数据。

初版完成要求 A—E 覆盖材料分类／组、形态、静态洗矿／合金／电解／离心、有效世界生成、unit 规则及两 viewer 的共享图；其他动态族允许明确列为部分覆盖，但不能写成“所有来源完整”。同步、生命周期和权限没有验证的部分不得计为通过。

检查代号与命令沿用[总计划](README.md#检查的使用方式)。原始快照、性能采样与截图留 `work/material-system-refactor/`；公共契约、纯图算法和稳定样例进入对应真实测试源码集。落地后同步包索引、API 使用文档和检查文档。
