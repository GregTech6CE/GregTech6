# Java 注释规范

注释用于帮助读者在关键位置做出正确判断，聚焦当前代码的行为、约束与原因。

## 编写原则

- **移植差异**：说明原版 GT6 的行为、本端当前行为及差异原因（API 缺失、平台差异、数据模型或性能考量）。
- **不变量**：记录注册顺序、单位与比例、优先级、线程模型、存档/网络格式和初始化时机。
- **平台与兼容绕行**：说明加载器差异、Stonecutter 条件分支或兼容性补丁的触发条件与影响面。
- **公开 API 契约**：为 `api/` 中的公开类型、方法与边界条件提供完整的 JavaDoc。
- **纯数据表逐行来源**：`generated/` 目录、带 `GENERATED` 文件头的生成文件，以及文件头标注 `// source-rows` 的手写数据表可保留逐行来源信息。

## 写法约定

- **聚焦当下**：说明代码当前的语义与本端后果；改动脉络交给 `git log` 记录。
- **本仓库引用**：JavaDoc 使用 `{@link Foo}` 或 `{@link #member}`，行内注释使用类名与方法名，依靠符号名称定位。
- **上游符号引用**：需要对照原版 GT6 具体行为、常量或公式时，使用 `{@code Class#member}` 或 `{@code Class.member(...)}`（每次标注一个主符号，并写清本端后果）；纯数据表的逐行转录可保留 `Class:line`（相对固定提交 `3703e40308c8c030763fd6297dea8b210d2a77b1`，2026-06-15）。本端独有代码或指向 `run()` 等超大入口时直接描述本端行为即可。

## 检查工具

`tools/comments/check_comment_refs.py` 负责校验非数据表注释中的行号引用、历史叙述与上游符号有效性；CI 的 `verify` 任务通过 `--diff` 检查新增注释行。注释是否言之有物仍由人工评审把关。用法与参数见[注释检查工具](../../tools/comments/README.md)。
