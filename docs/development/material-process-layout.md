# 配方总览图：拓扑分层与资源局部副本

本文定义配方总览图的目标呈现方式、布局步骤和验收条件，供后续实现使用。**已接入拓扑分层、连续链、局部副本与共享面板，游戏内外观及性能尚待验收**。当前接口、查询范围、资源身份与跳转契约以[展示接入](material-process-display.md)为准；本文不另建配方事实、公共 API 或查询协议。

## 目标与边界

图标、工序节点和有向箭头是主要阅读方式。玩家打开页面后直接看到已查询的加工步骤、主材料输入和输出，无需先选工艺区、展开目录或翻配方列表。悬停用于补充数值和条件，普通来源／用途查询用于进一步查看详情。

布局只依赖输入输出、资源身份、端口角色及已提供的关联。附属增加处理方式时，只要满足现有展示契约，就应自动参与排布；不得要求它先归入“机械加工”“热处理”等人工工艺区。来源、内部转换、回收、去向按实际消费输入、产出与结构化回收归属分类，按此顺序排列在同一画布上，并在有内容的相邻区域之间以竖向分割线区分，空区域不占空间；这不是按机器名划分的人工工艺目录。世界生成和泉沿真实 worldGenerated 标记进入来源区，通用回收进入内部转换之后的独立回收区。未能可靠分类的合法步骤在内部区保留，不影响准入。

规模增大时增加画布面积，利用现有平移与缩放浏览。默认构图优先保证物品和箭头可辨认，不强制把整图缩到一个小视口。该方案接受资源图标重复和较长画布，以减少交叉、长连线与额外查找操作。

范围仍是当前有界查询返回的 `Page`。布局不递归补查其他材料、不扫描配方表、不把“图中没有来源”解释为不可获得，也不把潜在路线解释为玩家库存可执行的生产计划。

## 图形规则

| 对象 | 呈现 | 语义 |
| --- | --- | --- |
| 资源 | 真实物品／流体图标，必要的短名称 | 对应一个具体端口的显示代表；保留原生状态与选择器约束 |
| 工序 | 机器图标或统一的工序符号 | 外观相同的路线可共享工序；全部原生 `Step` 保留，辅料不画入图中 |
| 输入连线 | 资源 — 工序 | 实际消耗的主材料输入，不画箭头；辅料和工具通过 `+` 查看 |
| 输出箭头 | 工序 → 资源 | 对应可见原生输出；主材料多输出在工序附近分支，额外副产物通过 `+` 查看 |
| 资源局部副本 | 相同资源图标及 `↗` 标记 | 同一资源在另一个使用位置的展示实例，不新增资源或配方 |
| 回流 | 局部资源副本及 `↩` 标记 | 返回已有资源的循环关系；方向不因布局反转 |
| 未确认关系 | 虚线及不确定性提示 | 沿用 `confirmed`／`resolved` 的含义，不能只因是回流就标成未确认 |

辅料、催化剂、存在条件和额外副产物不作为图节点，也不扩展它们的生产路线。它们保留在原始 `Step`，由机器右上角 `+`、tooltip 和原配方展示数量、消耗语义和说明。该侧有本材料时显示本材料的全部消耗输入／产物；没有本材料时优先用 `main`，否则稳定选择一个非副产物的外部主端口。此选择仅压缩图面，不改变原始角色。

非 1 件数量或带单位的量显示在格子右下角，非必然产出的概率显示在左上角；未知概率显示 `?%`。共享资源优先使用生产端口的角标；不同批量保留紧凑多值或省略号及 tooltip，不能用某一变体冒充所有配方。

普通连续加工链表现为 `A—机器→B—机器→C`。同机器图标、同首个可见产物的多个配方共享一个工序，不同输入形态在旁边合成网格；辅料本身不画入图中。

工序名称和图标外观均不参与工艺分类；只比较端口材料与根材料的实际身份及结构化回收标记。多步链的布局不要求识别“粉碎”“蒸煮”等特定名称。

## 事实图与展示实例分离

实现中应分开以下对象；名称仅用于描述内部职责，不要求新增同名公共类型：

| 对象 | 必须保存的信息 |
| --- | --- |
| 逻辑步骤 | `Step.reference`、全部原始端口、条件、原生配方引用和解析状态 |
| 逻辑关联 | 原始 `Connection` 及其资源、源步骤、目标步骤、确认状态 |
| 端口关联 | 步骤、输入／输出侧、端口位置、角色，以及该端口的原始 `Port` |
| 资源展示实例 | 独立的实例键、展示共享键、对应的端口关联、是否副本及实例位置 |
| 工序展示实例 | 对应全部原始步骤引用及位置；视觉重复的路线共享实例 |
| 展示连线 | 对应的端口关联／逻辑关联、实例端点、直线端点、回流与确认状态 |

`Port.resource` 是快照内引用，`Port.identity` 是现有契约定义的展示共享键。展示共享不授权 selector 与显示代表互换，也不授权不同原生状态互换。不能从相同 `identity`、同名图标或图上路径推导新的 `Connection`。

每条可见输入连线／输出箭头都必须能追溯到原始步骤端口；跨步骤关联仍以调用方提供且通过校验的 `Connection` 为准。图上复用显示代表时，需要保留各端口的候选集与约束，不得将多个 selector 的候选并成一份，总览共享只表示显示代表相同，不构成原生配方可执行或选择器可互换的依据。

副本实例键应由稳定的资源引用、所属步骤、侧别与端口位置派生，不能仅使用屏幕坐标或本轮遍历序号。所有实例都保留对应端口的原生导航数据。共享节点和副本按实际显示物品／流体执行普通来源／用途查询，不再挑选某一条配方精确跳转。全部原始端口仍留在实例和边的反查数据中。

数量、单位、概率和条件属于步骤及其端口，不属于共享资源节点。图面可在对应端口旁放紧凑角标；完整值仍由该步骤的 tooltip 与原配方提供，不解析展示文本来重建执行规则。

## 展示去重与原生事实分离

相似路线按机器图标完整状态、首个可见输出身份和通用回收标记直接合并，没有可见输出时才比较输入身份集合。次要输出存在差异的变体共用机器，并保留全部可见输出分支及其原生归属；它不表示这些分支会在同一次执行中同时产出。不同 `Step.reference`、辅料、数量、条件或 method 仍保存于原始步骤，但不再要求总览重复显示相同图形。未知图标没有可靠外观键，不能只因同为问号就合并。

所有原生步骤、端口、选择器、单位、概率及关联原样保留，合并边可以反查全部原始端口；它不改变配方注册项或 viewer 索引，也不声称执行等价。原生配方重复采集仍需在事实产生处处理，不能通过视觉合并掩盖数据问题。

相同 `Port.identity` 在同一区内优先共享一个资源节点，跨区保留带副本标记的材料实例，原生资源引用不同不再强制拆开。高连接度本身不触发复制，仅明显跨越多层且偏离主链的长连接才使用局部副本。统计区分原生配方数、显示路线数及资源副本数。

## 自动布局流程

### 保留完整端口，构造主材料图

从当前 `Page` 保留完整端口及原生引用，构造可见主材料资源—工序二部图，消耗输入指向工序，产物从工序引出。输出角色未知时保留 `UNKNOWN`，不按槽位或名称补猜。`Port.main` 只作为可见外部主端口和排布提示，其余端口留在 `+`；不能改变原始主副产物语义。

所有合法的已查询步骤都参与展示，不再因为无法归入 `Section` 或缺少可选的主 A／B 而跳过。世界生成仅使用真实 `worldGenerated` 标记；无输入、无生产者或无图标均不能被猜成世界生成。缺少查询范围外的来源时保留符号／范围提示，不补造生产配方。

### 处理循环并确定横向层级

在可见消耗流与输出中按稳定引用检测反馈边，排除工具和存在条件的非消耗连接。通用回收由快照统一核对 GENERIC 归属与研磨／熔化回收配方表，不能把同样使用 GENERIC 发布优先级的砧敲碎当成回收，判定入口见[展示接入](material-process-display.md#布局与交互)：它作为输入材料的用途保留，不作为目标粉末的来源；输出采用机器旁的回流实例，输出关联不向主生产链施加前向层级约束。其余步骤用迭代深度优先遍历解除回环约束，再对前向 DAG 确定层级；反馈边只退出前向层级约束，逻辑方向及事实关联继续保留。

前向图中，工序位置应晚于其参与排布的共同输入，产物位置应晚于工序。每个区域内部的层数来自依赖关系，不来自工序类型；有内容的区域最后按来源、内部、回收、去向拼接，区域间不绘制长线，原始关联仍保留在反查数据中。纯循环且没有外部入口时，用稳定引用选择布局锚点，不把这个锚点显示成“原料来源”。

浏览器草图用简化的最早生产层估计展示效果；生产实现必须覆盖无外部入口的环、自环、多个生产者及未解析端口，不能直接照搬草图中有限的合成数据假设。层级只表示阅读位置，不代表可达性、执行先后保证或最短生产方案。

### 识别连续链段并对齐

在已有层级上，首个可见输入与首个可见输出优先参与水平链对齐，顺序来自原生端口索引，再参考连接度、链长和稳定引用。原生首产物只获得排布优先级，不改变 UNKNOWN／PRIMARY 等事实角色。次要产物不会夺取该机器的主链位置。

将适合连续阅读的链段尽量放在同一水平线上，外观不同的替代路线及分叉就近排列。交汇点不能无条件合并所有相邻链段，否则一个公共原料会把全图重新拉成一个大团。这里的链段只用于坐标分配，不生成带工艺名称的分区，不删除原始步骤，也不要求玩家进入链段后才能阅读。

同一机器的本材料多产物按原生端口顺序紧邻排成至多三列、自动换行的物品栏网格，共用一根输出箭头。同机器图标和首产物的替代路线共用机器，不要求输入形态数、次要产物、概率或隐藏辅料相同；输入形态使用相同的网格与一根输入线。共享资源必要时采用局部实例；格子仍保留原生端口、独立导航和角标。链和网格按整块矩形预留空间后一起分配位置，并进行四轮邻接重心排序；随后按实际节点包围盒压紧和避让。局部副本只受可见边约束，原始 Connection 保留用于反查与确认状态，不再占据隐形依赖列。独立连通块使用各自的列宽、移除空行，再按矩形尺寸紧凑排列成多列；不同路线不会共用最长链和最宽网格的占位。优化顺序为：不遮挡节点与文字、减少交叉、保持连续链水平、缩短连线，再减少画布面积。相同快照输入顺序变化时，稳定引用应保证结果可重复；悬停和高亮不得触发布局。

### 选择资源局部副本

对造成明显扇入／扇出、跨多个层级、跨链长连接或回流拥挤的可见资源，在具体工序的输入侧或输出侧建立局部副本。可见产物与主输入均可采用该机制，不按工序名称或资源名单特判；隐藏辅料不参与复制。

当前副本选择处理跨越超过三层、纵向相距超过 128 单位、会穿过中间节点或属于反馈边的连接，以及偏离机器超过两行的次要输出，不按节点连接度直接拆副本。每轮拆分后重新排布，直到其余连接可以直接绘制；独立端口副本不再拆分。阈值仍需根据真实图调优。优先保留连续主链的直接连接及邻近分支的共享节点，避免无差别复制所有资源后把图拆成互不相连的配方小块。

副本应满足：

1. 图标、名称与明确的副本标记可直接识别，不要求点击才知道它是什么。
2. 同一资源的实例保留原始端口反查关系；悬停时可同步突出其余同身份实例及相关箭头。
3. 同名但不同 NBT／组件、相态或选择器约束的对象不因副本机制混为一体。
4. 以局部副本表达回流时仍标记 `↩`，不能看起来像凭空新增了一种外部供料。
5. 不为副本之间补画虚构的物料运输／加工箭头；标记表达展示引用，不表示新增配方。

### 端口排线与箭头

所有连接统一使用单段直线；连续链保持水平，分支使用斜线，不混入正交折线。输入侧只画线，输出侧才画箭头。输入和输出分别分配固定侧的端口位置，网格按整体侧边中点分配锚点，重复端口连线只绘制一次，悬停任一关联格均能高亮共享线；单个物品仍按自身侧边连接。密集多端口场景尚需游戏内确认。跨层边若会穿过中间节点，改用机器附近的资源副本。

回流和自环使用带 `↩` 标记的局部资源副本，保留真实输入／输出方向，不画跨越全图的回路，也不为回流预留顶部空白。没有节点的交叉处不画连接圆点，不同资源不能共用一段看似混料的总线；同一资源需要共线时，也应保留各工序的独立端口归属。

连线、虚线间距、箭头与图标使用同一画布缩放和平移变换，缩小时线宽和箭头同比缩小，不保持固定屏幕尺寸。箭头不能压住物品图标、数量角标或名称。回流使用副本标记，未确认关系使用虚线；催化剂／存在条件留在详情中，不画入图表。

## 视口与交互

打开页面即绘制全部已查询步骤及可见主端口；完整端口仍保存在数据和各工序详情中。有内容的区域同时存在于同一画布，不需要工艺区选择器、步骤列表分页或展开操作。有内容的分区标题及分割线随画布一起缩放和平移，空分区不分配空间。常用浏览仍是看图、平移和缩放；副本标记在未悬停时也可见。

初始缩放与复位采用可读性下限：小图可适配视口，大图保持可读比例并定位根材料的代表链附近。可用 `max(可读缩放下限, min(1, 整图适配比例))` 作为初始策略；具体下限根据游戏 GUI 缩放、物品尺寸及字体实际验证。若保留整图鸟瞰，应为显式操作，不能每次打开都自动把节点缩到难以辨认。

沿用现有资源左／右击查询、机器和资源左／右击普通来源／用途查询与 EMI ingredient provider。高亮优先使用悬停，不能直接照搬草图的点选锁定而占用这些原生点击动作。EMI 图标使用原生槽位与 tooltip，鼠标、释放、快捷键、收藏及物品拖拽沿用 EMI 绑定；共享面板及 JEI 的常规图标提示只显示名称；只有 `+` 区域显示合并配方数与去重辅料名，不提供右击切换隐藏变体。

所有副本的绘制、命中、tooltip、点击和原生 ingredient provider 使用同一展示实例及相同视口变换。未解析关系仍保留说明与关系提示；资源副本不绕过快照 generation 校验。

## 接入现有实现

| 入口 | 当前职责 |
| --- | --- |
| `MaterialProcessSnapshot` / `MaterialProcessGraph` | 继续作为事实与有界查询来源；图布局不额外枚举数据。重复采集如需修复，单独定位事实来源 |
| `MaterialProcessProjection` / `MaterialProcessDisplay` | 保留完整原生步骤、端口及确认关联，不以图标推断关系；副本实例属于布局结果，不成为新的 `DataKey` 或配方事实 |
| `MaterialProcessOverview` | 按原生端口和已提供关联计算依赖层级、连续链、副本与路径；保留原始端口反查 |
| `MaterialProcessPanel` / `MaterialProcessArrows` | 消费布局结果，绘制主材料图、副本和回流；调整默认缩放与复位，统一实例命中和裁剪 |
| JEI / EMI 适配器 | 继续复用同一模型与面板；资源副本仍使用具体原生状态查询，索引不随实例数重复注册 |

此表是现有入口的改造范围，不新增包职责或规定新的公共类。纯拓扑计算应与渲染 API 解耦，以便自动验证；无需为此次展示改造修改材料注册、存档、原生配方单位或附属处理方式注册要求。

布局按快照／页面、视口相关尺寸及字体尺寸缓存。平移、缩放和悬停不能每帧重算全图；重载或 generation 变化时释放旧实例和回调。渲染时可以做视口裁剪，但所有已查询节点仍须存在于布局中，不能把离屏节点当作删除或截断。

当前 `MaterialProcessDisplay` 接受最多 512 步、4096 条关联、每步每侧 128 个端口、每端口 16 个图标。这些是现行输入边界；752 步的浏览器演示只是界面压力样例，不证明生产页可接收该输入，也不构成提高上限的决定。

副本最多恢复到每个可见原始端口一个实例，资源实例总数不超过可见端口数；工序数不超过原始步骤数。该内部成本界限不删除步骤或原始端口，辅料和副产物仍留在工序详情。查询已截断时继续显示准确的覆盖提示，不显示“完整生产链”。

## 验证与实施顺序

自动验证覆盖原生引用、层级／循环、连续链、局部副本和排线，随后在共享面板中检查原生交互与可读缩放。只有真实样例证明需要时再调副本阈值，避免以某个工艺名称增加布局特判。

| 场景 | 必须满足的结果 |
| --- | --- |
| 八步链、多种替代配方 | 连续路线可直接沿箭头读；全部原始步骤保留，外观相同路线只显示一次 |
| 多输入、多输出、概率与未知角色 | 所有端口属于正确工序，隐藏辅料和副产物仍可在普通配方查询中查看，概率和约束不被共享节点覆盖 |
| 高连接度原料与副产物 | 优先共享同一资源，只有明显长连接才使用副本，标记可见；统计能区分事实数与实例数 |
| 未分类的新处理方式 | 仅提供合法输入输出即可排布；改名、换语言或新增 method 不要求增加分区规则 |
| 回收环、自环、无外部入口的环 | 布局终止，无伪造来源；反馈边及副本仍保留原始方向和回流标记 |
| 相同图标，不同原生状态或 selector | 原始约束与导航目标保留，不产生伪关联或任意替换 |
| 同名机器、同 A／B，条件或辅料不同 | 总览合并相同外观，保留所有原始步骤；图标点击执行普通来源／用途查询 |
| 纯符号资源、未知来源、未确认连接 | 保留节点与范围说明，不猜世界生成，不把回流等同于未确认 |
| 百步及接近现行上限的图 | 节点／文字不重叠，箭头不穿节点；保持可读比例，布局成本有界 |
| 相同快照打乱输入顺序 | 布局稳定；每个输入输出均能反查到原始端口 |
| 缩放、平移、GUI 缩放与重载 | 命中和图标一致，旧快照无法跳转，无离屏误删 |

拓扑自动检查应验证：每个原始步骤均能反查对应路线实例、所有可见端口可反查，隐藏端口保留在详情、布局不新增逻辑关联、副本可反查、包围盒不相交、前向边满足层级、反馈关系保持，以及相同输入的确定性。截图与性能记录应包括逻辑节点／关联数、副本数、布局耗时、画布尺寸、GUI 缩放和实际可读比例；不能只以编译通过判定可读性。

实现后的检查命令按[验证入口](validation/README.md)路由选择。人工检查覆盖 Forge／NeoForge、JEI-only／EMI-only／双装、无 viewer 专用服务端及远程客户端；使用[矿物处理展示页检查](validation/checks/manual-ingame.md#矿物处理展示页)并在实现时同步其旧分区、共享唯一节点和辅料变体切换预期。测试数据只放在已接入的测试位置，不写入生产配方表。

当前拓扑、确定性、副本、循环与交互坐标可由自动检查验证；真实材料图、游戏内小视口、两平台 viewer 交互和运行性能均尚未按本设计人工验收。完成接入时同步[展示接入](material-process-display.md)的现行行为说明与相关检查文档；不得提前把本文的目标行为写成已经实现。
