## 6. 下一轮开发建议：按闭环推进，不继续堆批次数

1. **先处理上述快速验收的失败项。** 实机测试是当前缺少的证据；渲染失败只补相关修复，不把所有系统重新推倒。
2. **完成矿处理专项。** 按原版处理器逐条列输入形态、主产物、副产物、宿主、概率、时间、能耗、流体和条件；补洗矿/离心等剩余分支。退出条件为代表性金属矿、宝石矿、特殊矿、小矿、岩石和粗矿的守恒/概率测试通过。
3. **补材料与生存断点。** 从 JEI 可见高级主控反向追原料，优先不可制作的基础部件、特殊材料形态、ANY 替代、缺失上游；同步检查普通 Minecraft 合成/切石机/回收形成的增殖循环。不是给所有物品随便写一个低成本合成表。
4. **做完整物流/数据协议。** 以实际物流核心和线/覆盖板端到端调度为验收单元，再推进无线、USB/HDD。不要仅再注册更多外观方块。
5. **逐种收口核、高科技和多方块。** 核对过载、停机、概率、存档、端口与系列材料及制造；每种机器保留原版出处和一条实际运行测试。
6. **单独推进世界生态和长尾交互。** 树木/采胶/蜂类遗传是完整子系统，不能用通用方块替代。现代 Minecraft 新内容的适配与原版忠实移植要分别说明。
7. **最后全链联调。** 新档完整生存路线、多人、旧档迁移、第三方 Tag 兼容、客户端资源；通过后才收缩剩余清单。

每一步允许跨多轮完成。交付标准是“具体玩法 + 原版依据 + 可制造路线 + 自动测试 + 待人工验收项”，不是新增数量。额度有限时优先第 1–3 项，后续暂存此清单即可。
