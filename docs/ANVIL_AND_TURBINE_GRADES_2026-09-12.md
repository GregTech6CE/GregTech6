# 砧立体展示、自动投料与燃气涡轮等级续批

## 本轮内容

### 砧上的锤子

对照原版 `gregtech/tileentity/tools/MultiTileEntityAnvil.java` 的形状 8/9：锤头为 4×4×6 像素，长柄为 14×2×2 像素，放在砧面 Y=12 像素以上。左右槽与两个水平轴分别映射。

上一批已经有这两个包围盒，本次没有将“补一个包围盒”当作新修复。新增 `AnvilHammerDisplay` 明确分离工具的视觉身份与可使用性；磨损工具或旧存档工具不会因为不可使用而退回扁平物品贴片。锤头、锤柄分别读取材料，缺失材料退回钢与木材。

新增 `AnvilCuboidRenderer`，砧上材料与锤子使用实体格式顶点、方块图集及实体 cutout 渲染层；法线经 PoseStack 的法线矩阵变换，避免把区块局部坐标法线用于实体相机。锭的宽度修正为原版 3 像素。

局限：尚未启动图形客户端，没有直接复现当前画面的最终 GPU 表现。无界面顶点测试能证明立体几何、朝向、UV、颜色、光照字段正确，但不等于已经完成客户端视觉验收。

### 砧的自动投料

依照原版 `canInsertItem2/canExtractItem2` 接入 Forge 物品能力：

- 两个槽可由任意面输入砧/小弯折/大弯折配方原料。
- 存着锤子时不允许自动投料；不允许自动抽取。
- 模拟不改变库存；返回的槽内容为副本，不允许管道修改内部 ItemStack。
- 实际投料触发存档标记与客户端更新，原有拆除掉落逻辑继续处理这两个槽。

### 四个燃气涡轮等级

原版注册位置：`Loader_MultiTileEntities.java` 的 17231–17234。

统一定义入口 `content/multiblock/GasTurbineDefinitions.java`，材料、普通功率、最大功率、墙体和硬度集中定义。

- 镁铝合金转子级：不锈钢外壳；普通 6144 HU → 4096 RU，最大 12288 HU → 8192 RU。保留 `large_gas_turbine_main`。
- Trinitanium 转子级：钛外壳；普通 12288 HU → 8192 RU，最大 24576 HU → 16384 RU。新增 `large_gas_turbine_trinitanium`。
- 石墨烯转子级：钨钢外壳；普通 24576 HU → 16384 RU，最大 49152 HU → 32768 RU。新增 `large_gas_turbine_graphene`。
- Vibramantium 转子级：精金外壳；普通 196608 HU → 131072 RU，最大 393216 HU → 262144 RU。新增 `large_gas_turbine_vibramantium`。

HU 是燃气配方产生的内部热值，不表示能直接往控制器灌入 HU。当前执行器沿用最大负载工作方式。

各级结构为主控 + 35 个实心墙体，整体 3×3×4；燃料进入前侧，废气接口在底部，RU 从后端输出。对应墙体为致密不锈钢、致密钛、致密钨钢、致密精金，拒绝低级墙体替代高级墙体。旧最低级继续接受同材质 `tank_wall_dense`。

燃料/废气罐容量随等级扩大，燃料事务、输出堵塞和 NBT 保留共用执行器。三个新主控注册了方块实体、创造栏、物品/方块材料染色、JEI 燃气配方入口和各自的 3D 结构预览。现有 Jade 通用检查显示对应等级的 HU/RU 缓冲与流体容量。

新增致密精金墙 `dense_adamantium_wall`；致密钨钢墙复用现有 `implosion_compressor_wall`，因为两者原版结构 ID 都是 18023。避免重复物品和相同输入配方冲突。两者均使用原版纹理与对应材料颜色。原版焊接路线：4 张对应致密板 + 选择器 10，64 GU/t、512 ticks，产出 1 个墙体。

精金原导入漏掉原版 `G_INGOT_MACHINE_ORES` 的锭类形态。本轮恢复锭、复合锭、板、复合板、致密板及可锻造标记，让通用加工器生成上游路线；其它组内全部工具/机器零件形态仍需继续核对。精金有 `MELTING` 但没有 `FURNACE`，因此同时阻止通用加载器因新增锭形态而给它添加普通熔炉熔炼。另补精金 9 板 → 1 致密板的压缩机配方，16 GU/t，时间按原版难加工材料 `9 × 256 × (工具等级 + 1)` ticks 计算。共享材质模型系统负责新形态外观，不新增每材料一份重复贴图。

结构端口共用方块补上自身掉落；不将旧主控绑定写入掉落物。新增测试逐一验证所有结构端口掉落一个对应部件。

## 集中游戏测试

1. 用已组装的硬锤右键空砧的左、右半面；绕砧观察锤头厚度、柄与头的连接，以及金属/木柄颜色。旋转砧重复测试。取回、退出重进后再看。
2. 用物品管道向砧投递可加工原料，应在砧上立即显示；试投递无配方物品应拒收。放锤后应拒收原料，管道不能抽出砧上内容。拆砧检查内容只掉落一次。
3. JEI 搜索四种燃气涡轮主控，查看结构页与燃气配方入口。各级结构页应显示对应材质墙体，共 35 个。
4. 依照预览搭建实心结构，前面供甲烷等燃气，底部排废气，后端连接能接收该级最大 RU 包的机器。检查 Jade 状态和缓冲。
5. 拆掉墙体应立即失效，补回恢复；高级结构换一块低级墙体应拒绝成型。断开后端设备时应保留 RU，不继续吞燃料。
6. JEI 查看致密钨钢墙与新增精金墙的焊接配方，检查放置颜色与背包预览一致。

## 构建经验

本轮在同一工作目录并行执行 `runGameTestServer build` 和补充 `compileJava` 时，后者出现 `.gradle/8.8/fileHashes` 缓存锁超时。最终验证改为串行执行。今后 IDEA 正在执行 Gradle 任务时，不应同时从终端启动另一个 Gradle 构建；`check_registration.py` 内部也会调用 Gradle，需排队执行。此锁超时不是 Java 语法错误。

后续焊接检查继续发现精金致密板未注册，已补原版锭/板形态组。这是配方前置物品缺失，与前述钨钢同输入冲突分别处理。
