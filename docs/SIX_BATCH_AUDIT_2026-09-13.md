## 回归中发现的底层注册问题
RegisteredFluids 的导入声明采用 `fluid(...).withGas().withTemperature(...)`，FluidEntry 是不可变 record。旧工厂先将基础对象放入注册表，后续 with 方法只更新了 Java 静态字段，Forge 实际读取的仍是旧对象。结果包括蒸汽相态/密度/温度错误，以及其他气体、药水标志、隐藏等后缀属性丢失。本轮在导入 bootstrap 阶段一次性校准已命名的最终定义，再生成材料派生流体并提交 Forge；新增全字段一致性与实际 Forge 蒸汽属性测试。新内容 registerDefinition 直接提交最终值，不依赖这层旧导入适配。

通用 FluidTankGT 仍有重要待办：其 isFluidValid 返回 true，proof 标志目前并不在通用 fill 内强制执行。本轮便携容器和流体工具使用显式耐性策略，引擎/锅炉使用专用入口限制；不据此宣称所有其他罐体已具备材质耐性。这个问题纳入第三/第五批接口梳理。

注册修正同时保留 Error/隐藏等离子体的旧注册 ID；隐藏行为移到创造列表过滤，避免因修正属性而删除旧存档映射。酸性材料按原版 acid 工厂归类恢复已存在材料的 ACID 标志，包含原版视为腐蚀性流体的氨；没有按名字带 Acid 与否猜测。

新增测试导致旧雨水用例的位置落在沙漠；测试夹具现用 fillbiome 固定自身小区域为平原。生产代码的干燥/寒冷生物群系不收雨规则保持原样。
