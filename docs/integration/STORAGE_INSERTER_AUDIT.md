# 存储输入器缺口与大容量存储交互去重

2026-10-22，第一百一十九批，基线 `74c5e8326`。上一轮提交垃圾设备物性／资源核查与源码整理，属于实际进展。本批新增 ALIGN-413，并重新盘点源码范围，见[回执](verification/storage-inserter-audit-20261022.json)。六份原版、14份当前生产Java、19段源码引用和一个实际Neo原生Inventory字段留痕；摘要只支撑列明的消费者，不代表整文件或全系统已经对齐。原树只读，GregTech-6 Team／Gregorius Techneticies和LGPL来源声明保留。

## 确认缺少存储输入器

原版 `Loader_MultiTileEntities:153` 把32751注册为 `MultiTileEntityStorageInserter`，有钢制四重管、蓝宝石／绿宝石／钻石及工具的合成声明，硬度／抗性6／6、默认物品上限16。它不是一个仅供调试的空名称，也不是普通大容量存储方块的别名。

原版点击入口及两个辅助方法构成独立批量存入流程：

- 根据点击面确定扫描起点，先向下探查；随后在四个水平方向逐列推进，循环上限50，遇到对应终止条件关闭该方向。每列检查地板及上方最多七层，地毯与碰撞阻挡分开处理。
- 只把朝向走道的原MassStorage宿主作为目标；已有内容的目标先尝试，空目标先放入列表、之后再处理。这是多个方块的扫描与顺序策略。
- 手持物品时只处理当前手中物品；空手时再遍历主背包9号起的槽位。`ST.nonautoinsert`会排除禁自动存入项、火把和弹药；空存储还限制自动接纳不可堆叠物品。
- `tryInsert`调用原MassStorage的真实 `insertItems`，把剩余物品写回玩家原槽，最后更新玩家库存。不能把方法中的NEI检查参数误写成模拟插入参数；原方法还用它识别NEI无限数量。

当前两端的实际存储注册类、启动调用、大容量存储点击和实体insert均已核对：普通大容量存储能手持存入，也有对**当前这一台**存储的背包存入区域；没有对应的独立输入器和跨多台存储的扫描调度。对当前明确源码根中的1826份Java做名称／32751边界筛查也未命中。旧汉化中仍有“存储输入器”键、存储页还沿用32751分类键，都不会凭空注册一个可运行方块。

因此新增413，范围是独立设备的注册／制作与上述批量扫描入口缺失；没有把已有的单台存入功能算成缺失。未移植这项设备，也没有用一条名字相似的单台交互代替它。实际注册关系不是仅靠搜索证明，原类、当前目录及实际调用者分别留证。

充电衣柜同样出现在本次筛查候选里，但它的60材料家族缺失已登记为 ALIGN-143，见[既有核查](SAFE_LOCKER_AUDIT.md)，本批不重复新增。

## 两版大容量存储交互共用

原 `MassStorageBlock` 在Neo段保存一份boolean交互、在Forge的use里又写一份相同业务。此次抽成一份共用的private interact，保留Neo原生useItemOn／useWithoutItem和Forge use作为薄适配。拆封工具识别集中到private isUnpackingTool，内部仍分别调用原NeoToolBindings或Forge GTToolHelper，没有把两种匹配机制强行换成一种。

完整比对两份旧业务：只按列明规则归一早返回的boolean／InteractionResult、等价短路守卫、taken局部名和限定类名；Neo的一行状态消息增加花括号，Inventory.items的var明确为ItemStack，实际原生字段确为NonNullList<ItemStack>。两份规范化正文与共用正文的572个有序token相同。扣物、创造模式条件、按钮优先、消耗、信息提示、材料存取及返回结果保留。其余Forge1295／Neo1483个token及其它注释完整保持，不宣称原始整文件字节相等。

另展开Neo的GTMetalChests：注册循环、属性、两种箱体和查找方法分别成行，m／w／b九处标识改为registeredChest、registeredWoodChest、chestEntry。完整Neo代码流经这三个名称归一后保持。两文件合计368→396行；共用交互减少重复，展开注册增加可读行数，不能把总行数变化当作架构完成率。没有改注册ID、顺序、配方、外壳保存、clone、工具模式或其它方法。

## 范围重盘与验证

明确维护目录仍有1826份Java，参考原版1229份；loader／loaders／a／b／c目录匹配为0。该结果只表示这些路径已整理，压行注册和其它职责拆分仍有剩余。受保护的用户WoodMaterials.java和CompoundMaterials.java未修改。

重读此前112份audit回执，341个原文件有匹配摘要引用，91个注册类候选未被这项严格筛查命中。**这些数字不是完成比例，也不能把91项都称为未移植**：它不扫描所有历史证据格式，也不是完整继承／条件注册图。充电衣柜就是已审查却仍被该筛查列出的反例。本批从候选中沿实际代码确认输入器缺失，未把机械搜索当作功能判定。

两版compileJava通过：先Forge源码实际编译成功、Neo缺离线EMI元数据；补齐同版本API文件查找后，最终增量任务成功，报告耗时1分钟。最初还遇到包装器缓存锁／下载超时，以及Forge映射依赖目录元数据缺失。只把五个已有且摘要相同的JAR复制进本机预期缓存，没有生成假POM或覆盖不同内容；它仍未修复默认离线索引。最终验证用临时初始化脚本直接提供相同版本的本地API文件，项目构建配置与依赖版本未改，不能宣称默认离线构建或GitHub CI也已通过。

本批没有游戏、GameTest、真实批量存入世界测试、存档重启、打包、推送或GitHub写操作。413是累计差异编号，不是未修数量；完整原版核对、存储输入器移植、现有差异修复及剩余源码标准化继续，goal保持active。
