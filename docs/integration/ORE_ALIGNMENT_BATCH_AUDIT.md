# Consolidated ore-processing alignment

## Bounded production changes

- **Raw Crusher/Hammer:** source-proven ORES-NO materials do not receive fabricated builtin raw-input rows from the owned entry caller. Shared block/vanilla callers, retained item IDs, rocks, furnace, dust recycling and manual conversion are not globally suppressed.
- **Sluice:** the same ownership policy applies to whole/tiny inputs and each registered water variant. Immutable definitions now retain fluid outputs as defensive copies. Water-specific keys and exact admitted recipe identities protect startup incumbents and final datapack replacements; no signature sweep or map-wide purge is used.
- **Magnetic separator:** a recipe-local84-positive ID/name overlay restores paired-source magnetic classifications. Omitted/addon identities retain legacy UNKNOWN behavior. Opposite-class selection and declared product order are preserved. This is not an exhaustive source byproduct/form catalog and does not mutate global material flags.
- **Ti/Fe whole dust:** unchanged builtin Titanium/Iron self-target dust emits144mB molten fluid in the Smelter at519/830 ticks, respectively, with16 stored recipe energy units. Their source targets lack FURNACE permission, so this generic producer does not emit Melter rows. The old102/94-tick fallback and unwanted Melter rows were observed in both native baselines. Cinnabar's16 legitimate thermal rows remain unchanged.

The53 source-NO identities are documented in `nonore-input-source-profile.json`. Sand remains UNKNOWN; the controlled fixtures retain one accepted Bakelite startup override. Materials activated by supported external raw-chunk/crushed bindings conservatively retain their continuation chain. This is not a claim that every recipe for all53 materials is removed or that every ore-processing producer is now source-exact.

## Verification and limitations

The shared baseline is10 cases in one fresh JVM per loader: exactly four named semantic failures and six controls passed. The fixed group adds one fluid-descriptor contract, for11 cases. Both actual fixed native groups passed after the canonical-composition guard correction. The first incorrect538-count fixture and first Ti/Fe presence-guard failure remain distinguished from source-oracle corrections; no expected output, chance, quantity or work was weakened.

Both loaders passed each of the two separate real reload profiles, preserving literal ordinary output checks independently from startup/datapack winner checks. Each completed two tag/datapack rounds and actual restoration, with exact nonce/world/ordered-pack/private-pack cleanup receipts before success; hard timeout taints only the disposable run and aborts subsequent profiles. A lifecycle pass is not inferred from the static cohort or from two different JVMs opening different worlds. Same-JVM new-world behavior is not claimed.

`check_nonore_batch.py --phase fixed --baseline-log <same-loader archived baseline.log>` performs the local cross-revision comparison of preserved semantic multisets, including duplicate rows. CI has no archived local baseline and instead checks literal source vectors, exact controlled cohort/override classifications, accepted rows and warm selection. It must not claim that this substitutes for universal addon/NBT parity. The standard857-case suite remains separate. To avoid duplicate native runs, the new CI runner group was not rerun locally: its exact11+1+1 profiles were already executed manually on both loaders with the migrated strict checks. Six synthetic runner scenarios exercised real checker subprocesses and fail-stop behavior; they are not native orchestration evidence. Hosted CI executes the new group in fresh JVMs/worlds. The final local gate passed the actual normal857 cases (Forge433 and Neo424), dual builds and core checks,259 Python guards,491 REMI guards, packaging/refmap checks and SDK checks (1049 shared classes;119 core and46 native API classes). Input/final runtime source snapshots were identical. The26 targeted native cases (11+1+1 per loader) are additional, not part of857. Six migrated public checker invocations revalidated their actual reports and cleanup receipts; hosted runner execution remains pending publication. These results prove the bounded profiles and current-form compatibility, not universal ore-chain parity.

Remaining producer coverage is explicit: general thermal target/ratio/work rules outside the reviewed identities, Centrifuge/Shredder and Petrotheum/cracking outside their bounded profiles, other raw Crusher bonus/host rules, slurry recycling water variants and fractional units, Anvil producer/work differences, informational byproduct displays and other source-unknown material facts. Anvil positional behavior and unsupported late grade-tag rebinding are unproven/deferred questions, not asserted gameplay defects. Packing and manual raw-to-gem conversions have their own original listeners and are not forbidden merely by ORES-NO. Existing rawcraft positional tests preserve that distinction.
