# P3 — Native turbines, dynamos, heat exchanger and original fuel rows

Neo registers all four original steam-turbine housings (17211–17214), four original dynamos (17221–17224), four original gas-turbine housings (17231–17234), their twelve existing modern alias IDs and the real heat_exchanger_main. Original and alias blocks use the same typed entities and source-grade data, avoiding duplicate energy stores or generic placeholder controllers. Steam/gas structures use the shared 35-cell 3x3x4 geometry and six-direction axis transform, with atomic claims and live role-gated ports. Dynamos keep the original 17 walls/18 copper coils, front RU and rear EU. The original material/rating tables, conversion rule and steam-condensation constant are shared by both platforms.

The source steam executor produces two consecutive RU pulses, condenses 170 L to 1 L distilled water and preserves pending pulse/remainder state. It keeps the source's deliberate voiding of excess distilled water and waste-energy converter dissipation. The gas executor reserves source fuel/exhaust on copied stacks, retains blocked rear RU output and uses the source fuel map rather than burning unrelated items. The heat exchanger uses one shared exact 17-cell, axis-independent two-layer layout, source hot-fluid plans, eight upward HU outlets and bottom cooled-fluid output. Source heat dissipation at unconnected outlets remains intentional. Stop/soft-hammer/plunger interactions, overload state and long-energy/NBT fields are retained. Neo uses registry-aware native fluid serialization and the existing legacy fluid envelope reader; this is not a tested old-world compatibility guarantee.

Eight original fuel-map schemas and all 37 original Loader_Recipes_Fuels rows (9 engine, 7 gas, 17 burn, 4 hot) are now owned by core and called by both platforms. Source negative EUt/duration, charge amounts, water/CO2/pahoehoe outputs and missing-fluid skip semantics remain unchanged. The fuel charge BigInteger calculation is shared; stack matching/consumption is a platform boundary over the same recipe identity model. Fuel schemas without rows do not establish additional controllers or recipes. Native initialization actually calls the original adapted loader, so gas/hot controllers are not connected to empty new lookups. Full survival reachability is still unverified.

The source nine-tile 48px idle/active rotor pass is registered for native steam/gas entities with native vertex APIs. Material tints are connected for all registered structural parts/controllers and their original named/alias precedence. The original fallback tint-material table is shared with Forge. Loader-free identity files are shared; Forge composite bytes stay in the Forge boundary, and native models only adapt the loader namespace. World visual output, six-facing lighting and animations remain unverified. Original source/target hashes, author and license evidence are in core/provenance/native-turbines-heat-fuels-integration.json; obtainable original histories remain preserved.

Comparison and selection retain the full implemented saltnya fuel/steam/generator baseline over shared domain primitives and atomic bindings. Existing brokestar weighted routing/masson loaded/actual reception integration remains in the same project; no alternate namespace, unit precision or new material/energy registry is introduced. This is an implementation choice with code evidence, not a claim that every baseline subsystem is optimal.

Grouped core/Neo/Forge compilation passed in 19s after connecting missing original control/fuel dependencies; the final compile including native rotor/tints also passed in 19s. One ordinary Neo short startup passed in 4m46s, covering the preceding tank/boiler registration wave too: 50 structural parts, 76 multiblock manufacturing rows (8 still unregistered/unresolved), 28 actual source fuel rows (9 skipped for missing fluids), 6406 total crafting recipes, 200 ticks and normal save/stop. The Mojang public-key timeout was nonblocking and was not retried. This is registration/data/startup evidence, not formed-machine gameplay; no new subsystem fixture or detailed test is added under D010. Actual assembled structures, fuel/exhaust/energy/condensation/pressure/tools/survival, world client rendering, Forge gameplay, real separate-process world restart, old saves and fresh jars remain unverified. Large crucibles, high-tech/logistics controllers and remaining original content continue next; The overall port is still incomplete.
