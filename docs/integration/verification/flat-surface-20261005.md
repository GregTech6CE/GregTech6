# 2026-10-05 / 双版灌木、液体泉扁平化与机器模型

在 NeoForge 1.21.1 测出的反馈，同时按 Forge 1.20.1 的修复与验收范围处理。本批两版均已实现并生成新的成对 JAR，整体移植仍未完成。完整回执见 [实际记录](flat-surface-20261005.json)，只读原版与 SDK 来源见 [来源记录](flat-surface-source-20261005.json)。

## 实现

- 棉花（原版产出线的默认灌木）及八种原版食物浆果分别注册为九种方块；空灌木仍可用标本种植。物品、掉落、选取、放置、创造栏及生成枝条使用实际变种身份，种类不再写入新物品或新方块实体的 `berry` 字段。阶段、支撑方向保留为方块状态，生长计数仍作为运行数据保存。
- 四种油、天然气、地热水和熔岩泉分别注册为七种方块。流体和原版产出参数来自不可变定义，新的物品与方块实体不保存 `spring` / `amount` 身份字段；激活状态仍可保存。模型、物品颜色和无方块实体数据的世界模型直接使用对应流体。
- 旧空泉 ID 从创造栏隐藏，保留为旧数据入口。已知旧灌木和泉在服务端首次 tick 转为对应注册变种，灌木阶段／支撑／生长计数、泉激活状态保留；泉的任意旧参数按该种原版固定参数规范化。无法映射的旧外部种类仍保留旧数据，避免静默改成另一种内容。
- 按要求移除支持者证书的注册、方块实体、Nexus 测试建筑位置、创造页引用、语言与八个模型／方块状态资源。Nexus 设施检查从26项调整为25项，证书位置明确检查为空。
- 两版材质与物品显示包装器传递真实物品渲染通道，并对复合模型每个子通道保留包装；修复包装后丢失层、空模型的问题。Forge 补齐基础机器共用模型烘焙入口。NeoForge 灌木颜色事件使用实际模组 ID `gregtech6`，颜色保留不透明 ARGB。

## 验证与修正记录

每版有限新世界各检查九种灌木和七种泉的注册、方块实体覆盖、普通物品身份、原生掉落／选取／`BlockItem.place`、采收复位及流体放出；灌木原版计数溢出通过直接调用实际 `grow` 检查。生成器实际放置45个对应种类的枝条，两个旧标签转换样本保留运行状态。这里使用提供的检查位置与服务器 FakePlayer，不扩大为自然发现、生存取得或完整时钟生长验证。

两版实际世界中的16种变体模型、六个闪电处理器／熔化器模型均通过修正后的最终错误门禁。旧回执的六个模型检查曾在最后门禁之后执行，不能据旧计数认定模型有效，已在 [旧机器记录](machine-recipes-20261005.md) 显式更正。NeoForge 早期两次失败分别是颜色事件注册 ID 和复合模型通道丢失；修复后两版最终各只有一个成功 marker，没有失败 marker。最终 Forge 世界 ID 为 `668ca66f-7d4e-4d91-b5ed-0b956fb184c5`，NeoForge 为 `bace2ab6-2962-400e-9a3f-3c53c32c9832`。

实际停止后的两版 region 文件各读出16个保存方块身份，种类确实位于保存的方块调色板，新方块实体没有对应身份字段。这是保存文件检查；旧标签转换是原生实体夹具，均不算独立重启／旧存档兼容验收。

最终普通双版 assemble 用时6分10秒，676个当前共享 class、当前平台 class、ZIP CRC、元数据、Mixin 和测试内容隔离通过。只对32个新增模型／方块状态文件和两份语言做本批字节比较，并确认八个证书资源及证书 class 已从两包移除；没有重复读取全量七万项资源或运行完整 GameTest／材料套件。

安装成品标题检查使用实际安装的 Forge 47.4.26、NeoForge 21.1.252 和 Java 25，在 `C:/Dev/GregTech6/build/production-smoke/` 新建隔离目录，不改整合包。最终两版各渲染16种变体加六台机器，检查七种流体图层、36个阶段颜色及六台机器材质回调；两张1280×720截图均已查看，图集没有被旧物品覆盖。Forge 渲染182帧、NeoForge180帧，正常退出0。世界截图中两组探针曾重叠，清晰的成品图集作为本批物品视觉证据。
