# Reliable EMI 全部列表／搜索折叠补修

用户确认环境为 1.21.1 NeoForge + 最新 Reliable EMI。本批暂停 Stonecutter 试验；试验提交 `3b8d41fde` 留在 `experiment/stonecutter-emi`，当前修复在 main。

## 原因与范围

此前 `41a751a61` 只生成了 56 个原料／加工形态组。创造栏分类不等于 Reliable EMI 的 `stack_groups`；工具头、材料方块、板条箱、保险箱、导线／线缆／管道没有相应折叠资源。这解释了用户截图中“上面有分类，全部列表仍展开”。

按用户后续补充继续扩大为 346 组，保留原来 56 个资源 ID：

- 材料物品的全部 107 个注册前缀，从实际物品定义目录读取，包含 36 个工具头形态、unit、子弹、木／塑料箭、轮子和单根铁轨等；成品工具保持独立。
- 25 个材料方块形态，从实际方块前缀目录读取；块、机壳、不同容量板条箱、矿石形态分别分组。
- 16 个裸导线线数组、5 个绝缘线缆线数组。1x 导线与 1x 线缆分开；同规格合并所有材质。
- 7 个流体管规格、6 个物品管规格；限制型物品管、四合一／九合一流体管保持独立。
- 普通保险箱、带锁保险箱分别归组，精确物品列表来自 `SourceCreativeCatalog`。
- 145 个功能／状态组：同种机器跨材质；普通／加固蒸汽引擎分开；固体、气体、流化床及各自致密型共六种燃烧室；普通／强化两种锅炉。另含坩埚、模具、龙头、箱子、脚手架、普通／排队漏斗、drum、不同规格轴、铁轨／动力铁轨／检测铁轨、面板、覆盖板及物流覆盖板。
- 全部 80 种蜜蜂按普通／已扫描的四种蜂状态分为 8 组，共 640 个身份；六种容量罐头分别跨食物分组；反应堆燃料棒、枯竭棒、增殖棒、产物棒分组，单件控制部件保持独立；食用浆果与材料浆果灌木均有分组。
- FluidItem 展示物品单独一组；27 种石材按 16 种加工形态分别合并，完整方块与半砖分开，共 32 组、864 个身份。组标题复用已有代表物品的完整语言键，不按该代表物品的石种限制成员。

原有部分配方标签仅包含铜类或铁钢类管线，因此显示分组采用有首尾锚点的注册名规则，避免修改配方标签的语义。原有材料组继续使用原生形态标签，保留处理木板排除项。Reliable EMI 仍为可选依赖，不改玩家配置或已经保存的展开偏好。

所有组名最终复用已有语言键，管线／功能／石材使用代表物品的完整名称。曾尝试去除代表材质名，但严格汉化门禁拒绝 209 项变化；该尝试已撤回，en_us / zh_cn 与原有文件完全一致，未放宽语言规则。`generate_remi_material_groups.py --check` 同时检查两种语言键与资源，CI 增加这一轻量步骤。功能组使用名称目录内的精确身份列表；蜜蜂／燃料棒／覆盖板分别对照实际种类、状态和行为目录，未用整个创造栏分类替代功能分组。

## 核验方法

新增仅 NeoForge 测试源码 `RemiGroupingSmoke`，通过 `-PremiGroupingOnly=true` 启用。新建隔离测试世界，等待实际 EMI 加载和索引线程完成，检查 REMI 的 `displayedStacks`：全部列表及真实异步 `@gregtech` 搜索中都有所需折叠项，组内物品不重复铺开，管线规格不混合；打开真实物品栏并通过搜索框输入查询，调用 REMI 自己的交互入口展开／收回保险箱，确认成员没有被隐藏或删除。该探针与下载的第三方测试依赖均不进入正式模组。

第一次运行只在世界 HUD 内检查，未激活 EMI 搜索面板；全部组检查通过，但展开数量断言失败，不记为通过。检查 REMI 的搜索钩子后补上实际物品栏前置条件再测。原始失败日志保留，不以 Gradle 的退出 0 误报游戏检查成功。

第二次自动检查停留在物品栏并超时，不记为通过。后续把自动步骤统一放在原世界渲染回调中驱动，允许该专用模式在物品栏打开时继续执行，避免屏幕／世界两套回调互相等待；同时把用户追加的类别纳入实际组断言。

第三次检查未等待搜索面板稳定，搜索过滤断言失败；明确激活 INDEX 面板、调用真实异步搜索并等待完成后，第四次得到 `WORLD_CREATION_SMOKE_SUCCESS`，159392 ms。原始索引 69079 项，全部显示 5466 项，`@gregtech` 搜索显示 5026 项；保险箱展开后 5086 项，再收回到 5026 项。所有必需组存在、默认折叠、成员没有单独重复列出，管线规格检查通过。前三次失败均不计通过。

运行时使用当时的 313 组资源，其中 299 组有至少两个成员并被实际检查；最终仅改了组标题语言键，没有更改这些组的成员。之后用户补充的 FluidItem 和 32 个石材组仅做注册目录、生成一致性及正式入包校验，没有再启动游戏。探针已追加这些形态的必需组，留待下次运行。截图实际捕获的是 HUD，不能作为物品栏视觉证据；后续移除该误导字段。未进行 Forge + REMI 的客户端实机验收，也未对任意具体材料搜索词或玩家已有展开偏好逐项验收。
