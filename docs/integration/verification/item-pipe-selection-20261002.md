## 实现与取舍

两平台保留 saltnya 的管道库存、六向连接、过滤盖板、入侧/回流限制、注册和原 NBT。继续使用此前从 brokestar 吸收的加权路径松弛及 masson 的 loaded-only/32,768 上限和有效余量记账。来源文件与原散列在 core/provenance/item-pipe-selection-20261002.json 中逐项记录。

旧适配器最多对六个邻接管道分别扫描共享网络。现在它们只收集合法的第一跳，交给同一 WeightedItemPipeRoutes.bestExit 扫描一次并返回第一跳，保留等成本时原 Direction 顺序。原 minimumExitCost API 保留并调用同一个算法，避免维护两套搜索。循环管网/零步长可终止；饱和 Long.MAX_VALUE 成本的有效路径不再被初值排除。

32,768 个已访问管道的预算现在属于这一轮共同搜索，超大网络可能较旧六次扫描更早达到上限；这是明确的规模边界，不把它描述成全规模性能已验证。masson 的缓存拓扑/预约系统没有额外导入。

ItemPipeTransfer 增加只模拟的出口探测，平台 ItemPipeTransferAdapter 同时承接探测与真实搬运。异常/无效余量的出口会被拒绝，而不让选路扫描通过旧直接 helper 抛出异常。拆管回送也使用同一模拟、刷新目标、实际送达记账流程，并只访问已加载邻居；仅扣已确认送达量，其余留给原掉落处理。两版拒绝非正数提取，避免负数请求让源库存增大。第三方已修改库存却不报告有效余量的副作用仍无事务保证。
