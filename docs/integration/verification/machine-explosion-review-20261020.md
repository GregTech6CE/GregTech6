# 2026-10-20 机器爆炸入口核查

范围：按用户要求检查产线中的爆炸风险，以本地原作者 GT6 快照为准，修复移植误判，保留原版明确的危险。用户提供的百科 6.07.18 蒸汽涡轮说明作为补充核验条件；没有把百科的默认配置描述误解为所有配置下都永不爆炸。此前暂停的全面功能审计不恢复。

## 本轮发现和处理

1. **远距离变压器绕过配置损坏。** 原版发送端过压和接收端过压都调用 `overcharge`，受默认关闭的通用损坏／爆炸设置控制；移植版两个分支直接 `destroyBlock`。现统一接入原版过载效果，模拟查询仍无副作用。
2. **大型锅炉用旧压力判爆及丢失未加载缓存。** 结构不完整时，旧移植在冷却之后仍用上一次仪表值判断爆炸，并提前返回，读数可持续过时。现与原版一样先处理沸腾／冷却，更新实时压力，再判断结构损坏、热缓存和蒸汽满罐。原版结构检查在炉体区块尚未全部加载时保留旧成型状态，现补回该缓存，避免误判失效及额外阻断已加载的输出口。区块未加载不作为结构损坏；全部加载后发现真实缺墙仍正常判爆。仪表统一使用原版 `UT.Code.scale` 的正数第一档，不能把工作中的绿色压力误当作可安全拆除。
3. **直接爆炸主控可能重复爆炸。** 原版通用 `explode` 会移除故障机器。移植版基岩钻、物流核心只请求世界爆炸；若主控因抵抗／事件取消等原因仍在，后续输入可重复触发。现先移除主控，再请求原版强度 6 的爆炸；已移除、被替换的旧实体不能再次触发。普通锅炉 tick／爆炸入口也拒绝旧实体回调。
4. **基岩钻缺少原版缓存优先保护。** 原版缓存大于 40000 RU 时先拒收所有后续能量，不检查后续包的过压；整批合法输入可短时超过软上限，存档也保留它。旧移植把输入和读档强行卡在上限，丢失这个状态。现与物流核心共享纯 Java 原版注入计算，恢复整批接受、软上限优先拒收和存档保留，不改变 4096 RU 的过压阈值。

之前修正的 `machines.explode_by_overload=false`、`machines.break_by_overload=false` 保留；旧的自动生成 true 配置键仍不生效。本轮没有全局关闭危险。

## 逐类结论

| 类型 | 原版／当前直接危险 | 处理或核查结论 |
| --- | --- | --- |
| 普通单方块机器、继承基础机的多方块主控、声明式机器 | 单包超过最大输入时通用 overcharge | 默认不破坏，明确开启设置后才损坏／爆炸。上一批已接入共享策略。 |
| 蒸汽涡轮、电动机、发电机、磁通／热能／电磁转换器 | 转换器前 100 次过载清空缓存保护；之后通用 overcharge | 保留原版缓冲和消耗公式；过量蒸汽默认不会请求范围爆炸。 |
| 活塞／旋转引擎、电池盒、普通变压器 | 通用 overcharge | 默认关闭；已有共享入口，没有发现另一条硬编码范围爆炸路径。 |
| 远距离变压器 | 两端过压均为通用 overcharge；超出导线承受值另有烧线规则 | 修正两端无条件拆毁，保留原版超额烧线条件。 |
| 自动点火器 | 通用 overcharge | 默认关闭。 |
| 自动锻造锤 | 正向 KU 单包超过输入上限时直接 explode，反向 KU 用作回程 | 保留原版特例，按包档位决定强度。 |
| 基岩钻 | 缓存未超过软上限时，RU 单包大于 4096 直接强度 6 爆炸 | 保留；恢复缓存保护、存档语义与一次移除。模拟查询不爆炸。 |
| 物流核心 | EU 单包大于 1024 直接强度 6 爆炸，满缓存先拒收 | 保留；保证故障主控先移除，避免重复请求。 |
| 26 种单方块锅炉 | HU 缓存超过容量、蒸汽满罐、带压拆卸／除垢 | 参数与原版登记相符；保留危险，统一实时仪表并防旧对象重复回调。热量等于容量不是过热。 |
| 5 种大型锅炉 | 同上，另有带压结构损坏 | 修正旧压力误判；保留真正超压、过热和满罐危险。 |
| 小／大型坩埚 | 爆炸性材料进入原版沸腾／燃烧分支时，按数量缩放爆炸 | 密度分支、触发条件、16U／432U 容量及强度 6／8 与源条件对应；没有增加普通金属过载爆炸。未完整实测所有材料。 |
| 1×1／2×2 核反应堆 | 当前原作者快照将地形爆炸调用注释；故障仍毁棒并有辐射 | 移植也没有地形爆炸调用。书籍中的风险描述不覆盖实际源码。 |
| 电线、机械轴 | 过载烧线／超速脱落 | 不是额外范围爆炸；现有原版烧毁／脱落规则保留，仍可能中断产线。 |
| 普通／多方块流体储罐、流体管道 | 过热熔毁、酸腐蚀、气体／等离子泄漏等 | 当前执行器未发现额外的压力范围爆炸入口；这些独立危险并未关闭。 |

主动使用炸药、点燃爆炸性材料、食物特效不属于机器输入误判。本表检查的是当前爆炸调用及相关破坏路径，不等于每个材料／机器／兼容模组的完整功能验收。

## 百科蒸汽涡轮条件

核查青铜涡轮额定 48 SU/t→16 RU/t、每 200 L 已消耗蒸汽回收 1 L 蒸馏水、默认过载无范围爆炸，以及朝上时活体的 5°／tick 和高于额定输出时 10°／tick。原作者实际 `onWalkOver2` 的目标是 `EntityLivingBase`，移植对应 `LivingEntity`；未扩大为所有非活体物品实体。

## 验证范围

最终双版编译及六个隔离 NeoForge 场景全部通过（2m26s），结果和 23 份原版来源哈希见同名 JSON。覆盖百科涡轮参数、锅炉压力边界、远距两端过压配置、基岩钻／物流核心直接爆炸特例和旧对象防重复、上一批通用过载，以及在远离测试加载区的真实区块边界保留缓存／区块加载后识别真实缺墙。

首轮五场景中四项通过；涡轮已经通过产出与蒸馏水断言，但旋转断言错误假设新建实体初始朝向是零。修正为检查实际 5°／10° 增量，并补齐未加载区块缓存后，最终六场景全部通过。首轮失败日志保留，不作为通过记录。

显式爆炸启动事件由夹具计数并取消，保护测试环境；不声称已经验证实际爆炸波及范围。没有使用用户产线或存档，没有完整测试集、全部兼容模组、真实客户端或独立存档重启。本轮静态检查不构成“所有机器永远不会误炸”的保证。
