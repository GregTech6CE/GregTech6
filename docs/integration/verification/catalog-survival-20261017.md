### `gregtech:grass` 与测试物品

原版 MultiItemFood 12000–12003 有草、干草、霉草、腐草物品；BlockBaleGrass 有四类对应草垛。以前 `GrassSoilCatalog` 把草垛纹理误当土壤独立注册为 `grass*`，这四个错误方块已去掉，旧 ID 指向正式 `bale_grass*`。草物品（当前 `grass_2` 等）保留。

`debug_scanner`、`chunk_eraser`、`worldgen_debug_wand` 在原版有明确声明，属于原版调试工具，不因名称带 debug 就当作移植占位物删除。测试储罐已经取消独立注册；没有按相似名称盲目合并参数不同的设备。

## 验证及边界

记录更新以最终构建／运行回执为准。首轮 NeoForge 定向运行发现 FluidItem 被真实流体组提前匹配，修正正则后复核通过；随后补查切割保色与最终排序，最终运行 c01da82d-8e72-408b-ba0d-52b6fcf212f8 全部通过，耗时 166621 ms。全部列表 872 项、GT 搜索 430 项；20 项源规则检查 0.271 秒通过。一次组合 unittest 命令误写了不存在的 test_localization 模块，正确的 test_source_policy 单独重跑通过；实际双语检查由 check_source.py 执行并通过。仅跑本批定向运行及轻量源检查，没有跑全套游戏测试。

[NeoForge 开发运行回执](catalog-survival-runtime-20261017.json) 检查新世界、38 条别名共用对象且旧 ID 不在注册表、191 条配方加载、20 类木半砖接入九宫格、288 条切割保色、电机电压顺序、三种枢纽矿砂、草垛干湿腐烂、EMI 全部列表／搜索折叠、保险箱展开／收回及 FluidItem 用途查询。

必须区分：配方被加载不代表每条都经过生存合成操作；开发环境运行不代表成品包实机验收。本批未验证 Forge 客户端实际玩法、真实旧存档保存重启、每种九宫格点击位置／半砖透明面视觉、每条机器生存生产链。改 ID 有读取别名，但旧世界方块实体内容迁移仍须在备份上核验。

## 建议人工复核

1. 在两版搜索存储四核处理器、钥匙、燃烧室、浇筑四件套、弹壳模具、耐火砖，确认原工具槽和材料均显示，钥匙输出三把。
2. 查看混合物、塑料罐、灭火器、玻璃、强化混凝土的加工路径；实际做一次青铜混合物和 HSLA 坩埚。
3. 输入两种颜色的玻璃／泡沫分别切割，确认半砖颜色；尝试木／玻璃半砖九宫格、合并双半砖、破坏掉落。
4. EMI 中检查电机等级顺序，FluidItem 按用途键能打开流体配方；展开战利品杂物、开孔木、桥和电池分类；检查 GT 内容没有进入 Minecraft 夹。
5. 用旧世界备份检查旧钥匙、耐火砖、旧储罐和重复主控能否保留物品数据、容器内容和结构；正式世界先不要覆盖备份。
