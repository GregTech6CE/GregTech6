# 筛粉漏斗余粉、钳子与 Jade

2026-10-22，第九十三批，基线 `e5d1846b7`。本批优先处理用户实测“小撮粉输入、小堆粉输出，混合多种材料后停住”；此前高级工作台候选仅阅读，未修改或登记成已确认差异。原版来源、实际修改、双版生成输入／编译输出和语言检查见[回执](verification/dust-funnel-fix-20261022.json)。

## 材料锁定与数量

原版 `MultiTileEntityDustFunnel` 的 `mContent`只有一种材料。输入必须与未清空的余量同材质；不足输出一份时保留余量，不会混合其它材料，也不会自动丢弃或自动改成最小粉末输出。当前共用实体的这条规则及五档数量与原版相同。

小撮为1/9粉，小堆为1/4粉，因此9小撮正好得到4小堆。例如某材料64小撮得到28小堆，剩1小撮；下一种材料会被余量挡住。这是按两份源码数量推导的例子，没有用它宣称复现了用户的实际库存、下游或世界。

| 输入小撮数 | 可输出小堆数 | 暂存量，以1/72粉为单位 |
| ---: | ---: | ---: |
| 1 | 0 | 8 |
| 2 | 0 | 16 |
| 3 | 1 | 6 |
| 9 | 4 | 0 |
| 64 | 28 | 8 |

资料中的“默认粉模式”与用户提供的原版快照不同：原类 `mMode=0`、`DUST_TYPES[0]=OP.blockDust`，注册32704没有覆盖mode。当前保留粉块默认值与已存档的模式，不重编号、不修改既有存档。活动扳手仍可正／反向切换五档。

## ALIGN-293：钳子取错储存层，已修复

原版钳子直接取出 `mContent`，保留输入／输出两个普通格。此前当前实现让钳子调用通用 `retrieve()`，它先取输出格、再取输入格，最后才取内部余粉；因此一次钳子操作可能根本没有清理阻止换材料的余量。

现在分开 `retrieveFraction()`与通用取物：钳子直接取余粉，按实际返还物质量扣除，不碰普通两格；潜行空手和拆除继续使用原通用路径。钳子按原返回工具费用10接现有统一扣费入口。清理余粉、切换输出模式后立即标记重新尝试搬运，避免单纯等待100刻重试。

从上方自动吸入现在复用 `accepts`，与手动／能力插入使用相同的粉末、单材料、当前余量材料和输出形态限制；不再保留一份较宽的旁路判断。粉碎矿石、纯净粉碎矿石不被当作普通粉末接受。现有向下主动输出和坩埚接收扩展保留，未改其它容器的全局通知链或原有侧面提取合同；ALIGN-172仍独立待核。

这次没有把余粉自动吐出，也没有让不同材料共用余量；用户需补足同种粉，或用钳子取出余粉后换材料。实际多材料产线是否还存在另一条故障，需要在更新后的包中重测。

## Jade 和语言

新增可选 `DustFunnelJadeProvider`，在既有插件中同时注册服务端数据与客户端组件。五种模式显示通用名称；服务端发送当前mode、内部材料身份和数量，不依赖客户端方块实体是否同步过这些字段。

有暂存量时显示材料及以1/72粉计的数量；仅在未达到选中输出大小时提示“补入同种粉末，或用钳子取出余粉”。例如64小撮的例子会显示8/72余量，而非把它误报为已经丢失。已有完整输入格、成品格内容并不计入这项内部余量。

新增八个中／英文键；既有语言键值全部保持。新模式标签按本次用户指定术语书写，属于新增Jade信息；没有改写原版汉化补丁已存在的文本。
