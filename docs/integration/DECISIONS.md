## 2026-10-20 / 附属管子的身份、档位和配方

附属管子挂在 `AddonMachineContributor` 上。一行流体管是 `FluidPipeDeclaration`：后缀、材料名、基础容量、防气、防酸、防等离子、防魔法、耐温和可燃性。耐温 `0` 按材料熔点的 1.25 倍计算，和内置行一样。一行物品管是 `ItemPipeDeclaration`：后缀、材料名、中号步长和格子数。步长至少 4，这样大号和限流大号仍是正数。

后缀按目录分开。流体管后缀撞上内置流体管或另一行附属流体管，启动失败，并写出两边。物品管同样。同一后缀可以一边是流体管、一边是物品管，因为路径分别是 `pipe_<档>_<后缀>` 和 `item_pipe_<档>_<后缀>`。

展开发生在内置行之后。流体管七档，细到九联。物品管六档，含三档限流。顺序是附属 id，再是声明顺序。内置 280 根流体管和 126 根物品管的 id 与 `gt6ce` 注册顺序不变。

方块 id 是 `<附属 id>:pipe_<档>_<后缀>` 和 `<附属 id>:item_pipe_<档>_<后缀>`。它们挂在附属自己的 DeferredRegister 上，接到 GT 的总线，不插入 `GTFluidPipes` 或 `GTItemPipes`。方块实体仍是 `gt6ce:fluid_pipe` 和 `gt6ce:item_pipe`，所以管子里的流体和物品跟方块一起存。

合成、焊接和材料回收走内置管子的同一套规则。缺 `plateCurved` 时，手工合成和焊接跳过这一行，不因此崩溃。已经有同材料同档内置管子时，焊接输出仍是那根内置管子。API 版本仍是 0。

## 2026-10-20 / 附属结构零件的身份、方块和运行时 id

附属结构零件是 `StructurePartDeclaration`：小写名字、材料名、附属命名空间里的贴图路径、正的硬度。贴图留空就用 GT 的金属墙模型，并按材料颜色染色。写了路径就是一张不染色的立方体贴图。名字是全局的。撞上 GT 零件名（含 `tank_wall` 这类别名）或另一个附属的零件名，启动失败，并写出两边。

方块和物品 id 是 `<附属 id>:<名字>`，注册在附属自己的 DeferredRegister 上，挂到 GT 的总线。这发生在内置多方块方块登记之后，不插入 `GTBlocks.BLOCKS`，所以后面的 `gt6ce` 方块顺序不变。方块是 `MultiblockPortBlock`，和现有外壳一样参与结构匹配和染色。运行时数字 id 从 1 000 000 起，按附属 id、再按声明顺序分配。结构匹配比的是世界里的方块，存档写的是方块注册名，这个数字不进 NBT。`parts()` 仍只返回内置外壳；方块实体的合法方块是内置端口加上这些附属外壳。

零件只是外壳。没有储罐、能量、物品槽，也不自己 tick。API 版本仍是 0。

## 2026-10-20 / 附属前缀的身份、单位量和物品

附属前缀是 `PrefixDeclaration`：名字、英文前后缀、以 U 计数的单位量、附属命名空间里的贴图路径、材料名单，以及可选的固定条件。条件只有有工具属性、可锻、不是木、不是煤、不是石、不是食物、不是肉。不能传自己的谓词。空名单必须带有工具属性或可锻；只有否定条件时不去扫全部材料。写了肯定条件时，命中的材料并进名单。没写时，否定条件只检查点名的材料，对不上就启动失败。

名字在核心前缀之后注册。和已有前缀同名、只差大小写、注册名冲突，或撞上 `casingSmall` 这种别名，启动失败。内置前缀的单位量仍走原来的名字表。附属前缀把声明的个数乘上 `U`。

物品 id 在自动形态和显式板、箔之后追加，顺序是附属 id、声明顺序、材料名。命名空间是附属自己的，不是 `gt6ce:`。路径仍是 `sample_blank_iron` 这种形状。同一命名空间里路径撞车就失败，不占用核心 id，也不改核心物品 id 指纹。贴图从附属命名空间取，一层，用材料颜色染色。坩埚和粉碎回收读这个单位量。前缀不自带加工配方。API 版本仍是 0。

煤是 Coal、Charcoal、CoalCoke、Lignite、LigniteCoke、Anthracite、HydratedCoal、PetroleumCoke。食物用 GT6 的食物标记。肉是 MeatRaw、MeatCooked、MeatRotten。

## 2026-10-20 / 行为机器的容量、出能和右键

容量缺省 0，tick 末尾仍按额定输入排空。大于 0 时，顺序是先收能、再跑行为、再把存能封到容量。`setCapacity` 改的是运行中的容量，只有调用过才写入 `gt.capacity`。旧存档没有这个键时用声明值。过充不由外壳爆炸：行为能在返回前看到存能高于容量，外壳只在行为返回后丢掉超出的部分。

出能要同时声明面、类型和每 tick 的包大小、包数。`emit` 从存能里扣，按面调用 `EnergyTransfer.emitEnergyToSide`，返回邻居实际收下的包数。超过声明上限直接失败，不截断。没有声明出能的机器仍不对外输出。`generate` 把能量加进同一个缓冲，容量为 0 时缓冲仍是额定输入上限，所以手摇这一类机器可以在排空前把一包能量推出去。

外壳继续只实现附属 `EnergyBlock`。`IEnergyBlock.getEnergyTypes` 和附属接口的同名方法擦除后冲突，不能两个一起实现。轴的连接、激光纤维、能量中继、远距变压器，以及配方机器、燃料机、轴式发电机、燃气轮机、避雷针、动能引擎这些邻居查找，改成 `EnergyBlockViews.view`。内置方块本来就是 `IEnergyBlock`，`view` 返回它自己，内置方块之间的传能不变。齿轮箱出能本来就走 `EnergyTransfer`，不用改。扫描仪、Jade 和盖板仍只认 `IEnergyBlock`。

`onUse` 缺省不处理，菜单照常打开。扳手和流体容器仍先处理。水车用已有的 `level()` 和 `pos()` 看相邻水，不加新入口。API 版本仍是 0。

## 2026-10-20 / 编程电路与不消耗的物品输入

附属配方收成 `Recipe` 时不设置 `mExplicitCatalystsOnly`。这个标志为假时，显式下标和 `RecipeCatalystLike.isCatalyst()` 的物品都算催化剂；为真时只认显式下标，模具和编程电路也会被扣掉。`SelectorTagItem` 以催化剂身份注册，所以附属行里的编程电路不写 `keptInputs` 也不消耗，写了只是再记一次显式位，不报错。
