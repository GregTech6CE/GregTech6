# P3 — Native molds, basins, faucets and crossings

All39 original crucible hull materials now have real molds, basins, faucets and crossings:156 actual blocks/items. SmelteryCompanionDefinitions shares original identifiers, meta offsets50/750/700/850 and hull amounts5U/5U/3U/5U; Forge MachineRegistry delegates to it. Basin cooling uses the same existing shared MoldCastingRules as the mold. Existing material identities, U precision, shapes and admission rules remain single shared contracts.

The native ceramic MoldEntity has been replaced with a thin facade over the full original MoldBlockEntity, which backs all39 actual mold variants. The existing bootstrap API/ID remains supported, including Direction-based fill, direct use/tick/drop methods. Previous native output preflight remains before admitting unsupported material forms when no basin is present. Native registry-aware NBT retains gt.mold.shape/auto_pull/use_redstone, gt.temperature/content.*, gt.mold.solid_output and explicit clear-content/clear-output sync flags. The full original chisel25-cell selection, recipe/fallback output, pincers pickup, tool wear, soft-hammer reset, directional/redstone pull and source basin stacking are connected. There is one executor rather than a parallel isolated ceramic implementation.

Basins retain original9U full-block fills, auto-pull and mold-above handling, cooling, stored solid output/tint, pickups, heat/proximity hazards and registry-aware gt.basin.* storage. Faucets retain directional crucible connections, immediate passthrough, acid/temperature guards,16-faucet downward chain, redstone tick policy and original facing/auto_pull fields. Crossings retain horizontal routing, redstone inhibition and original per-wave loop lock. Exact shapes, waterlogging, wrench/pickaxe harvest and actual drops are ported. Source event interactions and original companion tooltips are connected through native APIs and actual sound identity.

Original material-textured composite hulls, baked block/inventory aliasing, four directional faucet hulls, original inventory transforms/tints, full25-cell grid side/top rendering and molten/solid basin/mold content rendering are connected to native client callbacks. Additional models use Neo's standalone variant; renderer vertex calls and baked model maps use native types.527 resource records are shared original bytes, platform composite-loader adapters or explicit missing original registry scaffolds backed by the actual original baked hull geometry. No client rendering pass is claimed.

Source code comparison exposes baseline limitations that remain explicit: stacked mold paths clear an entire9U basin for smaller shaped outputs and use environment temperature in parts of the path; basin automatic solidification can clear material if the registered block output is unavailable; faucet downward search usesY>0 and shown interaction has no autoPull-toggle path; crossing lock cleanup is not exception-safe; mold/basin target solidification remains identity fallback. These are not treated as proven conserving gameplay. Complete39-material survival manufacture is not established by inspected original recipe registrations and requires actual source rows/mapping, rather than invented claims. Further source/function integration will address these alongside the deferred gameplay acceptance.

Source authors, SHA256, notices/licenses and preserved histories are recorded in core/provenance/native-smeltery-companions-integration.json; all three source trees are untouched.
