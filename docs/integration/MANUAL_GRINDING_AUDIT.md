# 磨石、研钵与磨削产物续核

2026-10-22，第九十八批，基线 `9de200988`。读取20份原版来源、23份当前来源及其中32份共享平台投影，另核两个本机原生工件中的四个条目。作者／许可证头、摘要、原20种磨削登记族、有限条件和完整排版证明见[回执](verification/manual-grinding-audit-20261022.json)。本批只审计、整理排版，不修玩法、不构建。

## ALIGN-304：世界保存有磨料，普通掉落物没有

原磨石 `writeItemNBT2`写入 `NBT_STATE=mStone`。这不只是一个未被调用的方法：06父类的final `writeItemNBT`先调用它，04父类的 `getDrops`再把返回数据交给对应多方块注册物品；原磨石读取同一字段。原剩余磨料可跟随普通采掘所得的磨石物品。

当前世界保存／读取明确写入 `gt.stone_uses`，安装磨料和成功普通磨削也会修改次数，不能报成“没有磨料计数”。但Neo的 `ManualToolBlock.getDrops`直接返回新方块物品；Forge默认战利品包也为这个非StatefulBlockLoot方块生成普通物品，没有复制实体数据的函数。共用盖板掉落补偿只筛选盖板字段，不包含这个计数。

确认缺少的是普通掉落携带磨料的路径，限无额外第三方掉落改写的正常磨石。世界内存档保留与挖成物品后再放置不是一项验收；本批没有运行实际收获、创造取块、保护取消、外部数据包覆盖或独立存档重启，也不建议让其它机器整份携带NBT。

## ALIGN-305：磨削余粉的75%变成默认必得

原Sharpening登记共20族：13种粗制工具头，以及7种磨削。7行都调用 `.chances(10000, 7500)`；`RecipeMapHandlerPrefix.chances`确实保存这个数组，生成配方时传入真实配方。非空余粉放在第二产物位置，原磨石再通过 `getOutputs()`按每件物品抽取，不是只影响查看器的显示概率。

当前同样有13＋7种声明，且已用 `MortarGrindingRecipes.pulverize`计算粉碎目标和余量。但带余粉时调用的是没有概率参数的 `addRecipe1`重载；这个重载交入空概率数组，`Recipe.getOutputChance`对缺省位置返回10000，实际手作流程继续调用 `rollOutputCount`。因此生成了非空第二产物的路线，其余粉变为必定产出。

以一件非空余粉的随机判定为例，0～9999中原有7500个成功值，当前有10000个，2500个值结果不同。这是源码概率域推导，没有运行随机试验或实际配方。不能把它扩大为“全部磨削产物都错误”：主产物仍为100%，没有第二产物的行不受该差异影响。最终配方覆盖／冲突及每种材料的实际形态仍待核。

## ALIGN-306：GT电动工具漏过去附魔排除

原 `UT.NBT.getEnchantmentXP(ItemStack)`首先拒绝 `ST.isGT_`物品，后者判断 `IItemGT`。电动矿钻等实际由 `ToolsGT.sMetaTool`登记；其 `MultiItemTool→MultiItem→ItemBase`继承链包含 `IItemGT`，所以排除范围确实包括原电动工具，不只是手工工具。原另有旧EU物品兼容检查，不能从它直接推定必须照搬某个现代外部模组API。

当前磨石的 `removableEnchantmentXp`只排除 `GTToolItem`，保留诅咒／附魔书门控。项目自己的 `ElectricToolItem`却继承原生 `TieredItem`；实际共用工厂遍历电动工具目录创建这种对象。它们还有材料附魔写入路径，不能因不属于GTToolItem就当作普通外部工具。

在电动工具已带有效、非诅咒普通附魔且进入磨石交互的条件下，当前可通过原本应拒绝的类型门控。这项为源码条件结论，没有实际制作、施魔或去魔测试，也没有宣称所有电动工具在所有材料上都自带同一种附魔。材料附魔的一次性标记／玩家附魔合并保护仍保留；本批未改它们。

普通XP公式不是新缺失项：两边都求各自版本的最低附魔费用之和，再除二向上取整。现代诅咒判定和数据包注册holder属于版本边界；公式相同不代表每种附魔在不同Minecraft版本中的费用值都一样。原与当前去附魔分支也都没有扣磨料，不能顺手“补扣”一次来改变规则。

## ALIGN-307：换物品后的点击计数政策不同

原磨石只存一个块内 `mClickCount`，手持非空且磨料已装时递增，没有保存／比较上一个手持物品。当前用 `lastHeld`比较物品和NBT／组件，不同时清零，再按十次门槛推进。

有限条件为：普通有效玩家、已有磨料、连续对A操作九次，接着换成另一非空B，期间没有其它状态变化。原第十次进入处理尝试；当前B只得到第1次，尚不处理。B最终是否有配方或可去附魔另有门控，不能据此凭空宣称会产出。

登记为待统一的操作政策差异，本批保留当前按物品重置，避免借排版恢复旧的预先累计行为。当前虽然保存了 `gt.progress`，`lastHeld`并未一同保存；首次交互还会重新比较，不能从进度字段存在便声称已完整跨重启续作。

## ALIGN-308：漏掉原挖掘疲劳的饥饿消耗倍率

原研钵、磨石及筛选台分别以总功率除250／10000／1000调用 `UT.Entities.exhaust`，磨石去附魔传0.5。这个共用函数还乘 `pot1Fatique`，普通无效果为1，疲劳I／II／III分别为2／3／4。

当前对应 `ManualWorkRules`仍有这三种基础除数，手作和去附魔却直接调用原生 `Player.causeFoodExhaustion`，没有乘这项效果。两版本机原生Player和FoodData的实际消费方法也已核对：普通路径直接加传入值，FoodData另有40上限，没有暗中补上疲劳倍率。

| 一次成功去附魔，普通玩家且不触及上限 | 原增加exhaustion | 当前增加exhaustion |
| --- | ---: | ---: |
| 无效果 | 0.5 | 0.5 |
| 疲劳I | 1 | 0.5 |
| 疲劳II | 1.5 | 0.5 |
| 疲劳III | 2 | 0.5 |

这四项是源码传参及原生消费者推导，不是饥饿格减少量或真实玩家测试。无敌／创造豁免、最终上限及第三方事件另算，不报创造模式一定扣饥饿；其它手作容器继续单独核查，不凭共用名字扩大宿主范围。

## 已有合同和013扩围

磨石的正常十次门槛、磨料安装／普通磨削扣一次、正面或顶面交互、去附魔／研钵产物给予玩家均有实际入口。磨料4／8／16次的自有材料表存在，外部矿辞磨料是否同样可用仍待核；当前的大整数换算避免乘法溢出，继续保留，不能为了旧公式文本一致恢复旧long溢出。

现有ALIGN-013补入磨削门控：原7行还排除COATED，rockGt行额外要求STONE，当前 `SharpeningRecipes`声明层未消费这两项。它与已有研钵／压缩的材料条件缺口同类，不另立重复编号；这里不宣称每种原涂层材料在当前都生成了对应可达形态。20种登记族的输入／输出身份对应，不代替全部材料、参数、概率和最终配方验收。
