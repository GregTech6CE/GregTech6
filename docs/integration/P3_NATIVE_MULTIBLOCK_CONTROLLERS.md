# P3 — Native multiblock controllers and manufacturing

Neo now binds the original 12 large recipe machine families and large matter fabricator to their actual structure-aware executors, rather than ordinary machine placeholders. Compact matter tiers retain source efficiency. Distillation uses the original 80-cell shared layout and source heat/item/fluid roles. Matter retains the 149-cell structure and original control/conversion processor counts. Binding validates every part before mutation, clears previous claims on failure/removal, and uses role-gated live item/fluid/energy relays without a second stored inventory. Port loading clears transient claims and resolves the actual controller. The source crucible forwarding boundary is preserved through an interface; this does not register or claim a completed large crucible.

Dedicated fusion retains the original 886 cells, interchangeable processor locations with exact 3/12/12 counts, input reservation, LU startup charge, continuous-reaction retention, timed EU emission and pending outputs. Its custom fusion tick is connected explicitly instead of invoking the ordinary recipe-machine tick. Implosion retains 25 dense walls and one explicit air cell, timed explosive recipes and 64-way parallel policy. Shared implosion geometry is called by both platforms. Original machine parameters and large/matter policy are in Java 17 core; Minecraft recipes, registries and stored stacks remain platform boundaries.

Original coke and cryogenic controllers are also registered with their native capabilities and NBT boundaries. The coke/cryo hollow shell geometry is shared with Forge, preserving the source's unconstrained internal cells. The cryogenic source executor is still a simplified input splitter, not a verified cryogenic recipe engine: 100 mB is divided by three, individual fill failures can discard outputs, and source metadata/progress does not establish completion. Coke keeps the original limited coal/wood detector and HU process. Source automatic output bookkeeping and injection overflow need later behavior review; no silent claim of conservation or advanced survival functionality is made.

The original manufacturing pack consumes the already shared source pattern table. Only registered blocks and resolved ingredient rows emit recipes; missing future controllers are skipped and counted, never replaced with generic ghost outputs. Neo adapts the pack lifecycle, singular recipe directory and result id codec. Existing original ingredient fallbacks remain, so loaded recipes alone do not establish the complete survival chain. Named structural parts remain separate original IDs; hosted part aliases resolve to their original preferred block. Controllers are kept in their own typed machine registries, avoiding registration of controller records as generic parts.

Original model identities and loader-free bytes are shared. Forge composite model bytes remain in the Forge boundary; native counterparts change only the loader namespace to neoforge. World rendering, tints and source preview/JEI integration remain unverified. Provenance, source hashes, authors, license history and comparison sources are in `core/provenance/native-multiblock-controllers-integration.json`.

Comparison with brokestar's bound structure checker and masson's world-access scanner favors keeping the existing atomic PartBindings and loaded-before-read validation while sharing immutable coordinates and rules. Neither alternate registry nor a second material/energy framework is copied. This code selection is provisional runtime evidence, not a declaration that every baseline implementation is best.
