# 大容量存储的工具、模式与封装核查

第四十四批，2026-10-20，基线 `ff30fdee0`。原版来源为 `gregapi/tileentity/inventories/MultiTileEntityMassStorage.java`，继续追踪胶带的实际宿主，以及两版方块入口、物品能力、工具类和物流子类。原作者来源和文件哈希见[回执](verification/mass-storage-control-audit-20261020.json)。

## 已有对应的路径

普通容量为 1000000；胶带要求当前未封装、有模板且库存量不超过预算，返回 `max(100, 库存量)`。刀或剪刀拆封使用 1000 的工具返回值，两版实际调用均交给 `damageForToolClickReturn`，并非只有一个未接入的 helper。

未封装拆除会散落整件库存；已封装拆除保留整件库存，但余料仍单独掉出，保存到掉落方块的数据会去掉余料字段。创造取物另保留完整数据。当前 `looseDrops`／`packedForHarvest`／Neo `shell` 已区分这些情况，不能把已封装库存保留误报为所有机器都错误保存物品。

六个按钮的取物数量 8、64、4、32、1、16 已保留；模板重置位和剩余部分材料的保留判断也已有代码。材料形态使用专属家族，不能把它扩大解释成同材料所有形态均可互换。本批没有对全部外部标签、按钮画面、真实破坏重放或存档重启作验收。

## ALIGN-136：钳子取物与软锤清空缺少实际操作

原版 `onToolClick2:127–182` 的钳子会取出部分材料、向玩家非快捷栏槽位移动库存、更新玩家／存储并发声。软锤会先清暂存槽，或分批向正面丢出大容量库存并处理余料；一次有上限，不能表述成一次清空百万件。

当前两版 `MassStorageBlock` 只专门处理拆封和螺丝刀，没有钳子／软锤分支；实体也没有相应的转移／软锤操作。GT 工具通用回调和 Neo 专用钳子类没有补上该宿主路径。已有的空手按钮取物不会替代“取到背包”与余料处理，普通物品能力被外部漏斗抽取也不会替代手持工具操作。

与此同时 `OriginalStorageTooltipData.massTools` 仍列出钳子和软锤提示。结论是该宿主工具入口缺失，不是钳子或软锤在整个模组都没有功能；没有游戏执行证据。

## ALIGN-137：自动下送／溢出模式只有提示和部分状态残留

原版剪线钳切换位 4 的溢出模式，活动扳手切换位 1 的自动下送模式，螺丝刀切换位 2 的模板模式。原版 tick 会在未封装时处理输入槽，并在库存变化／周期到达时向下输送；溢出模式允许容量临时增加 256，再把超出普通上限的部分向下输送。开启自动下送时，原版还禁止从底面输入。

当前实体只消费模板重置位 2 和封装位 8；低位虽然能经保存／恢复或掉落数据保留，却没有位 1／4 的切换、执行 tick、额外容量或侧面规则。两版方块没有对应 ticker，物品能力直接走同一个处理器；物流子类继承该行为，并未为这些位增加执行。

因此“活动扳手自动下送、剪线钳溢出”提示超前于实现。外部管道和物流网络仍能通过现有物品能力搬运，不应扩大为此存储完全不能自动化。

封装时原版仍允许切换这三种模式，当前在拆封分支之后直接退出，连已实现的螺丝刀模板模式也被阻断。这是模式门控的额外差异；并非要求封装状态下开放库存搬运。

## ALIGN-126 扩展：螺丝刀损耗没有按返回值换算

原版模板模式切换返回 10000，经通用工具公式对应 100 点基础损耗；当前两版方块均调用 `damageForUse(held, 1, player)`。这是已经记录的损耗合同问题在大容量存储的实际入口，不另造重复问题编号。拆封的 1000 返回值路径正确；不能把所有工具点击统一乘 100。

四份文件按实际源格式展开，共七份 core／Forge／Neo 词法与字面量比较通过。平台展开使用现有 `check_relay_sharing.project`，先解开维护源码中的 Neo 注释体再选择版本；同时补强上一批两份共享源码的对应证据，避免仅把被注释的 Neo 分支当普通注释过滤。
