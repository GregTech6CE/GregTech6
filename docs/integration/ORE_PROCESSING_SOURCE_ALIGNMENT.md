# 矿物处理原版对齐：有界规则修复与验证记录（待固定测试结果）

本批不是重写整个机器框架，也不代表全部材料、全部矿处理路线已经对齐。先用朱砂完整测试切片确认共享生成器错误，再按来源证据逐步替换；材料 ID、已有物品形态、机器库存布局和公开旧流体解析契约保持不变。

## 已确认问题与修复边界

- 水力筛矿为主产物加 **8 个独立概率槽**，共9槽；机器本来已有9输出槽，不需要扩容或迁移存档结构。
- 筛选机稀有宝石实际数量为1；8/4/2是相应形态不存在时的普通宝石替代数量，不能当作稀有宝石数量。Lapis不生成这些分级形态时使用原版替代；合法外部形态不能被一概禁止。
- 磁选只选相反磁性的副产品，保持原顺序；缺少细粒离心矿形态时退到**同一材料**的小搓粉，而不是换回主矿。
- 熔炉资格应依据原版有效 `FURNACE` 属性，而非仅有 `MELTING`。两个内置生成入口共同应用来源策略，避免另一生成器重新加入错误配方。
- 朱砂原矿 Crusher 的额外宝石由原版命名粉碎效果与副产品规则计算；不是为所有宝石矿统一增加随机宝石。
- 六种 Shredder 输入使用原版粉尘形态、重复输出槽和整数向上取整工时；不是额外矿物副产物。
- 纯净矿离心使用小搓离心矿输出和三项10%副产物；环境流体换算先按原版单位舍入，再乘整矿倍率。
- 原版确实存在 Petrotheum 筛矿、蜡+蒸汽裂解，以及朱砂 Cryotheum 浸洗成宝石的明确配方。不能仅依据界面中未见配方而删除它们。Cryotheum两种用量为25/13mB，其中13来自向上取整，不是12。
- Wood的原版工厂不生成矿石形态；只阻止旧生成器人为制造的内置 crushed→Sluice 路线。保留物品 ID、木材粉/板处理、熔炼目标元数据，以及真实外部矿物输入。

## 共享规则与有界材料证据

共享修复包括9槽筛矿、分级宝石数量/替代、磁性筛选、来源熔炉策略，以及独立的粉碎/离心/浸洗/裂解规则实现。

熔炉证据配置含 **215 个内置 ID+规范名称身份**：110个明确YES、105个明确NO。其余为UNKNOWN，继续保留旧行为；不能把导入表缺失当作原版禁止。审计时实际538个 crushed 合格内置材料中，67为YES、105为NO、366仍UNKNOWN。此统计是覆盖范围，不是整体完成率；外部附属材料不由该配置接管。

后续规则目前通过独立复核的**朱砂基线适配器**接入：校验ID9114、品质、粉碎/研磨目标与数量、四个副产品及相关流体身份。匹配之外、属性已改变或附属拥有的材料继续UNKNOWN。算法与材料证据分离，不能把这一切片说成所有矿物都已修复。

11项原版液体单位绑定仅服务已证明的路线：Mercury及8种Wax为144mB/U；Petrotheum、Cryotheum为250mB/U。来源注册名和现代原生ID分别核对，例如`molten.wax`对应`gt6ce:molten_wax`；没有更改原生流体ID或放宽为任意别名。

## 验证进展

修正测试夹具后，两端实际执行507项：Forge258中233通过、25失败；Neo249中224通过、相同25项失败。此前453项全部通过；两项新增控制（Sluice既有9槽持久化、附属配方覆盖重建保留）也在两端通过。25项均到达来源语义断言，没有发现/反射/别名夹具错误。

这些是**修复前基线**，不是修复成功证据。失败后的后续断言尚未得到验证。首轮生产候选Forge终态258项中254通过、4失败：Petrotheum完整/小搓路线、Magnetite磁选、Copper熔炉正控制。前两类分别是原生材料缺失但流体存在、导入磁性标记缺失；Copper暴露早期粉优先配方阻挡后期正确铸锭配方。已形成独立复核的有界后续候选，尚待实际重新验证；该轮Neo未运行。不能提前宣称507项通过。

第二轮Forge终态258项中256通过、2失败，揭示更深一层的差异，而非前次问题仍原样存在：

- Copper最初输出的是粉，属于生产错误，已通过让有来源证明的原矿/粉碎形态交给既有专用熔炉监听器修正。随后实际输出正确的`minecraft:copper_ingot ×1`，但测试错误要求移植自有`ingot_copper`的物品身份。原版OM允许注册统一目标，原生`RecipeMap.add`也确定性统一为原版Copper锭。因此只修正夹具为显式原版Copper锭，并新增其`ingot/Copper`材料形态身份断言；数量1、概率、工时、实际查找和原生RecipeManager断言均保留，没有放宽为任意别名。
- Magnetite磁选的候选、数量、概率与工时已正确，但Stone仍选中了移植版遗留的离心小搓物品。原版Stone的G_STONE不含ORES，正常基线应回退为Stone小搓粉18。后续候选只在配方输出选择中应用有证据的核心Stone形态不可生成判定，保留明确外部形态注册、附属所有权和UNKNOWN回退；不删除遗留物品、改变物品ID或全局材料形态。

这两项后续候选已独立复核。第三轮Forge终态258项中257通过、1项既有撬棍管道测试因原生实体掉落夹具区块未加载/未tick而失败；新增矿处理27项全部通过，无失败、错误或跳过。此结果确立Forge该切片的原生通过，但不是完整507项验收，Neo及完整门禁仍待后续结果。此前失败XML与旧夹具均保留，不能把缓存编译或部分断言通过当作最终游戏验证。

测试从实际已接受配方表读取，并核对`findRecipe`真正选择的身份、形态、数量、概率、流体、工时及EUt；不向表中注入期望配方。旧453项不能为新增测试让路。独立RNG控制验证每输出物品×处理次数的独立抽取；没有因此重写所有机器的随机逻辑。
