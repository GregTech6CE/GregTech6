# 材料轨道工具、检测与助推电源核查

2026-10-22，第一百一十一批，基线 `04386f1c4`。核对原版 BlockBaseRail 与当前三种材料轨道包装、工具入口及两端实际原生消费者，新增 ALIGN-367–369。两份原版／十份当前生产 Java、13 段引用、八个原生源码／字节码条目见[回执](verification/rail-controls-audit-20261022.json)。整文件摘要用于追溯，审阅范围以列明入口和片段为准，不代表外围功能均已验收。原树只读，原作者／版权和 LGPL 声明保留。

## 确认差异

| 编号 | 原版逻辑 | 当前逻辑与边界 |
| --- | --- | --- |
| ALIGN-367 | BlockBaseRail.onToolClick 接受撬棍切换轨道元数据，成功返回2000；助推轨另接受软锤切换第8位，成功返回10000。 | GTTrackBlocks 的30条材料轨道继承原生 RailBlock／PoweredRailBlock／DetectorRailBlock，没有接工具回调或 ToolInteractionTarget。工具识别／消耗 helper 已有，缺的是这些轨道的消费者绑定。道路条纹轨自己的工具切换反光位另有实现，不在此缺口内。 |
| ALIGN-368 | 检测和比较器查询均使用相对方块坐标 `(0.125,0,0.125)…(0.875,0.875,0.875)`。 | 两端继承的 DetectorRailBlock 使用 `(0.2,0,0.2)…(0.8,0.8,0.8)`，查询范围较小。边缘包围盒可能旧范围相交、现范围不相交；这是条件差异，不是已经跑过矿车的世界结论。 |
| ALIGN-369 | 助推轨递归传播先要求邻块 `== this`，即同一个注册方块；不同材料实例不能通过该门槛。 | 两端 PoweredRailBlock 接受任意该类实例，再核轨道轴向和 isActivatorRail。当前 GT Booster 全部调用 `super(properties,true)`，不同材料助推轨也能通过类型／模式门槛，并读取邻居电源或继续递归。 |

367 的调用链分别核了 GTToolItem.onItemUseFirst／useOn、前置 MultiblockTools、ToolInteractions 和覆盖板事件入口。前置多方块入口只处理建造杖／放大镜及对应方块实体；覆盖板事件要求 PanelCoverHost；通用工具描述要求 ToolInteractionTarget。材料轨包装没有这些绑定，原生轨道也没有相应 GT 工具分支。对维护 Java 的 BaseRailBlock／RailShape 相关搜索另列七个匹配文件，作为交叉检查；不把搜索结果宣称为排除任意外部模组或反射的证明。

原撬棍表达式原样是 `isPowered() ? (aMeta+1) % 10 : ((aMeta/8) * 8) + (((aMeta%8)+1) % 6)`。官方旧 JAR、Forge 映射与方法名表核实了 isPowered 的对应，未凭直觉交换其分支。旧实现临时改变 World.isRemote 的做法只作为来源记录，不建议直接复制到现代环境。

368 的有限几何例子：输入包围盒 `(-0.83,0.0625,0.01)…(0.15,0.7625,0.99)` 与旧检测框相交、与现框不相交。该算术没有生成实体，也没有证明任意行驶路径的持续时间／比较器波形。

369 的有界条件例子：不同材料 A／B 助推轨同轴、处于递归深度范围内，B 已通电且有外部电源，A 没有直接电源。旧身份门槛拒绝 B，现代类型门槛允许读 B 的邻居电源。未搭建真实红石网络，未将此扩大为任意网络都会通电。

## 已有实现与范围澄清

两端检测轨已有20tick通电复查、弱信号15和向上强信号15、状态变化通知及比较器更新。命令方块矿车优先、普通容器库存比较器路径也存在。现代 mod-cart 的 getComparatorLevel 扩展不属于待补原功能，不能因 GT 包装没重写这些方法就报全部缺失。

三十条材料轨道和普通 BlockItem 已注册。原版按轨道家族登记十种材料，当前按每种材料登记三个家族；已纠正“完全按原版注册顺序”的注释。没有仅凭该差别判断创造栏／EMI 排序错误，它们有独立消费者。

NeoToolBindings.isTool 委托交互工具谓词，craftKind 则先用 GTToolHelper.isTool 再转换 GTToolItem；两处意图不同，没有把门面方法名字当成转换异常证据。
