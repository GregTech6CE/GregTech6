# 瓶框与书架库存核查

第四十七批，2026-10-21，基线 `03be2061d`。沿原版 `MultiTileEntityBottleCrate`、`MultiTileEntityBookShelf`、父库存及书籍登记，核对共享代码、两版能力／配方入口和本地真实依赖源码。新增 ALIGN-147–151，并扩展已有音效、禁贴面范围；本批不修改玩法。

## ALIGN-147：失效物品缺少原版槽位替补

原版 `TileEntityBase05Inventories:54` 使用 `ST.load(tNBT, getDefaultStack(slot))`。`ST:1275–1283` 在原物品和 ore 字典恢复都失败后返回默认物品；瓶框 `getDefaultStack` 返回一只空瓶，书架返回普通书。这只发生在保存过的条目恢复失败时，不应给所有空格补物品。

当前两实体分别把 `gt_bottles`／书架库存交给 `ItemStackHandler.deserializeNBT`，没有槽位替补。已读取本地 Forge 47.4.20 的实现 `:186–200`（直接 ItemStack 解码）及 Neo 21.1.243 的 `:155–166`（parse 成功才填槽）；均未提供空瓶／普通书默认值。这里确认缺少原版恢复合同，未运行卸载提供物品的模组后重启，也不承诺直接导入原始 1.7.10 NBT。

## ALIGN-148：书架遗漏魔法材料的附魔基底

原版 `MultiTileEntityBookShelf:144–150` 返回 `(MAGICAL ? 1 : 0) + bookPoints/12`，普通书一分、附魔书两分。Thaumium 原材料明确为 MAGICAL，金属书架注册也不以外部 Thaumcraft 安装为条件。

当前 `BookShelfBlock:254–255 → BookShelfBlockEntity.enchantPower → GTBookList` 只累计内容书点／12，没有读 variant.material。当前确有 Thaumium 书架变种；空架原版应贡献 1，当前公式为 0。缺的是条件材料基底，不是所有书架都不提供附魔能力。修复还需核对相应材料属性消费链，不能无条件给所有架子加 1；未运行附魔台场景。

## ALIGN-149：内置陈列物登记未接入书架

原版 `LoaderBookList:33` 无条件将 Circuit_Selector 加入 BOOK_REGISTER，`GT_API:731` 有实际物品实例。`MultiItemTechnological:362–372,791–817` 也登记内置切片刀／模具、USB／HDD。电路只是可陈列取回、显示类别 43，不具有书架特有的模式控制功能；按钮、拉杆和火把的红石行为另有分支。

当前集成电路 0–24 和相应科技物品确实存在，但 `GTBookList.canPlace → BookShelfRules` 只接受固定 NORMAL／DISPLAY 小集合及彩色书。手动放入和物品能力都使用该过滤，所以这些内置陈列物进不了架子；渲染器也只有少量显示类别和普通书回退。下一步需要恢复登记与显示映射，不应只给几个 ID 绕过白名单。旧外模书籍的完整目录留待现代对应关系审查，不按旧注册条数直接认定全缺失。

## ALIGN-150：书架放大镜只显示名称

原版 `MultiTileEntityBookShelf:176–184` 对正／背面目标槽发送 `PacketItemStackChat`；包 `:93–99` 在客户端取完整 `ItemStack.getTooltip(player,false)`，仅在列表为空时回退名称。

当前 `BookShelfBlock:182–184` 只发送 `stored.getHoverName()`。无覆盖板时通用事件不会补内容提示；例如附魔书的附魔行没有对应显示。这与 ALIGN-125 的覆盖板过滤器诊断不同。放大镜工具成本仍属已有 ALIGN-126，本批不为同一个扣费遗漏再建条目。未验客户端聊天画面。

## ALIGN-151：创造模式书架插入消耗不同

原版 `MultiTileEntityBookShelf:247–251` 成功放入一件后直接递减手持数量，没有无限物品例外。当前 `BookShelfBlock:212–216` 只在非创造模式 shrink。两者均只向槽内放一件，但创造模式是否扣除手持数量不同。

这是一项明确行为差异，优先级低于库存恢复和内置物品接入；需要与各宿主的原版创造规则统一决定，不能擅自用全局“创造都不扣料”覆盖。瓶框当前仍会把整组手持搬入，已经遵循其原版合同。

## 扩展已有记录

- **ALIGN-132**：瓶框原版 `swapBottles` 成功取／放均 `playCollect`，Root 实际发送 MC_COLLECT。当前真实交互、库存变更和两版适配都没有该声音调用。当前整组转移与满包拒绝已有对应，不将缺声音扩大为取放失败。书架已有取物／按钮声音，不算全库存无声。
- **ALIGN-139**：书架原版 `allowCovers` 排除 facing 轴上的正／背两个陈列面，瓶框则所有面都禁贴。当前通用 fallback／安装路径未识别这两份宿主规则，普通装饰板可进入禁贴面。抽屉／保险箱只禁正面、大容量存储允许贴板后阻挡交互，仍是不同合同，不能全局禁所有储物方块的正面。

## 已有对应与不能据此推断的结论

瓶框九槽、64 普通栈限、全侧带瓶子过滤的物品能力、世界 X/Z 九宫格、整组入格和整组取回都有对应。`ST.add(...,true)` 的 true 是优先选中槽，不是背包满后掉地；当前先合并非手持、再选中槽、再空位的逻辑对应原版，满包不会部分转移。

瓶框原版选择框高 6px、碰撞高 10px，瓶身／内液／瓶颈的 27 个部分也已有公式对应。拆除库存应保留在瓶框物品内，原版 keepSlot=true／canDrop=false；当前快照覆盖先拆实体后求 loot 的顺序，packedStack 带内容，旧 handler 清空。该路径不能套用普通箱子的散落规则。实际完整旧档重启、创造／爆炸所有掉落路径仍待运行。

书架实际已有 15 个可用木架和 60 个金属架，75 个配方资源和清单可定位；原版 300 个木材索引包括不可用／隐藏／旧外模条目，不能直接用数量相减报告缺失。28 槽、每槽一件、正背各两排七格、四朝向坐标、基本书籍过滤、普通自动化、按钮 120 tick、拉杆锁存和控制物不自动抽取已有入口。

书架保存库存、两面待生成 loot、种子与红石状态；原版和当前都在交互／拆除及附近玩家周期中生成待定书物。原版同样遍历 14 槽 dummy 的空条目后替补书，不把该现象误报成移植新问题。书架普通拆除应散落库存，与瓶框整件保存不同。

父库存的爆炸随机清除、全部书籍显示图标／发光、现代可选书籍、真实多玩家／保护区、配方全部解析、旧世界重启继续核查。本批没有完成原生爆炸分派，不据 onRemove 一处就断言爆炸必定全掉或全毁。
