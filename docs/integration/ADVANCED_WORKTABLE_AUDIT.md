# 高级工作台蓝图、相邻资源与工具匹配

2026-10-22，第九十四批，基线 `b5943aba7`。筛粉漏斗玩家反馈已在该基线独立提交，本批恢复原全面核查。读取13份原版来源、27份当前来源及其中46份共享平台投影；来源摘要、作者／许可证头、八组槽位与完整排版证明见[回执](verification/advanced-worktable-audit-20261022.json)。本批只核源码和改善可读性，没有改工作台玩法。

## ALIGN-294：集成电路铺格入口缺失

原版 `GT_API`实际绑定 `IL.Circuit_Selector`，不是未注册枚举。高级工作台的30号槽明确允许2～9号选择标签；`getCraftingOutput`把实物集中到九宫格索引3，再按编号放置零数量样品，供合成查找和后续取料。八种形状已直接从原分支提取：

| 编号 | 九宫格索引，按0～8从左上到右下 |
| ---: | --- |
| 2 | 3、6 |
| 3 | 3、4、5 |
| 4 | 0、1、3、4 |
| 5 | 1、3、4、5、7 |
| 6 | 0、1、2、3、4、5 |
| 7 | 0、1、2、3、4、5、7 |
| 8 | 0、1、2、3、5、6、7、8 |
| 9 | 全部九格 |

当前已注册扁平化的 `integrated_circuit_0`～`24`，但工作台实体和菜单都通过 `isBlueprint`限制30号槽为两种蓝图。`pattern`只读取实物格／蓝图格，也没有编号铺格分支。因此缺的是正常槽位和铺格消费者，不能说集成电路本身没有物品或配方；菜单转移、NBT强制写入也不等于正常支持该功能。

## ALIGN-295：制作计划没有相邻可连接库存

原版 `getAmountOf`会计入六面 `ITileEntityConnectedInventory`。`consumeMaterials`先尝试这些相邻库存，再依次消耗本格多余数量、其它九宫格多余数量、储物／工具格和最后一件格内样品；余物也会尝试送回可连接库存。原 `MultiTileEntityMassStorage`确实实现数量、整份移除与插入方法，未锁定时有真实消费者。

当前 `plan`只复制71格本地库存，`source`只搜索该数组，返还也只调用本地 `put`。普通物品A在实物格里、旁边未锁定的可连接仓储有足量A且配方允许时，原版先扣相邻仓储并保留格内样品；当前消耗台内A。这是源码条件见证，不是已运行的具体配方。

原版支持的是指定的连接接口，不是任意原版箱子或任意模组库存。当前被动自动输入能力、外部管道往台内送货，也不能替代制作时主动从邻接资源取料。缺口同时适用于继承此实体逻辑的充能工作台。

## ALIGN-296：制作时补充流体容器的相邻储罐路径缺失

原 `consumeSlot`在消耗有返还容器的物品前，读取其中流体，检查空容器可完整回填成原物品，再向相邻 `ITileEntityConnectedTank`请求整份流体。成功后直接返回，原格内装液容器保留。原桶基类实现了该接口，包含锁定、同种流体和足量门槛；不能只看到接口便断言任何邻接储罐都能供给。

当前计划依赖原生配方的 `getRemainingItems`，并把空容器等余物放回本地格。制作链没有邻接流体查询／补充；两版注册仍连接这份共用实体，Neo工作台能力入口也只有物品、充能表的能源注册，没有补上制作补液逻辑。

本条条件是配方本身有效、容器能完整回填、没有相邻物品库存抢先供料、储罐未锁定且足量。它不是所有水桶配方都已失败的游戏结论，也不是断言外部模组永远不能添加能力。原版另有向16～20工具格直接灌液的入口，完整原生适配和手动入口仍待续；本批不从缺少一个注册项推定所有交互结果。

## ALIGN-297：同类工具额外受到头材料限制

原 `ST.equalTools`对 `IItemGTContainerTool`跳过NBT相等检查；`MultiItemTool`实现该标记，工具主材料实际存于 `GT.ToolStats`。原工作台数量统计、取料和多样性过滤都调用该比较。蓝图写入时还清理此类工具样品的旧NBT。

当前同类手工具按一种工具一个注册物品提供，主材料仍存于栈数据；但工作台 `same`额外要求两把工具可用且 `getHead(a)==getHead(b)`。当同种工具均已组装、可用、仅头材料不同，而配方接受两者时，原比较接受，当前比较拒绝。普通物品的NBT／组件严格相等并不属于这项差异。

例如格内工具A只有一件、储物格有同类不同头材料工具B，原本地取料可以先用B保留A；当前跳过B并退回格内A。这里只追到比较、搜索和制作计划消费者，未执行全部工具配方或磨损效果。该谓词也用于工作台过滤；不据此扩展为所有工具槽都无法制作。

这不是ALIGN-292的机器自动合成标签问题：原自动合成机器直接禁止手工具，高级工作台则处理玩家手工配方。也不能机械照抄原蓝图“清空NBT”：现代材料／组装数据有实际意义，后续修复须保留可用性、耐久和容器保护，不重新允许损坏工具。

## 已有功能与保留边界

- 71格布局、16／36两组储物、五工具格、九宫格、单张蓝图槽已有。限定本地部分，消耗顺序与原声明一致；八种访问／清格组合的槽位数组也一致，含非清格模式63／64的特殊顺序。回执中的八组是源码条件投影，不是实际能力调用测试。
- 实物格优先于蓝图样品；服务端计划复制库存，在找到配方、余物可存放后才提交。当前不在失败时先改真实库存；这些保护保留，不能为了接相邻资源而恢复原有余物丢失风险。
- 原生配方余物、Neo裁剪输入的格偏移、无限物品保留、玩家制作事件和配方授予已有。高级工作台与自动合成机器的余物策略需分别核，不能把后者每格容器查找套到这里。
- 预览有库存revision、RecipeManager、配方身份和重载generation门槛；已有事件入口只说明源码接线存在，不证明多人、空缓存或真实数据包重载已验收。
- JEI／EMI转移入口均注册到实际菜单，使用九格与真实库存来源；结果格使用独立虚拟地址。没有把“转移类存在”当作快捷制作、所有点击组合或客户端显示均通过。
- 充能工作台继承共用制作，五工具槽逐项接受能源包，声明无方块能源缓冲，Neo能源能力与Forge父能力委托已有。外部物品、全部能源类型、符号／极值和实际充电还没有完成验收。
- 继续保留已加载目标保护、复制／提交和存档尺寸修复。原非原版工作台危险材料、更多工具／音效、直接注液、完整批量点击和独立存档重启仍需核查；不因本批关注四项而缩小全面目标。
