# 工作台直接灌液、充能与结果点击续核

2026-10-22，第九十五批，基线 `26aeb95f7`。继续上批尚未完成的直接流体、充能和界面入口，读取12份原版来源、23份当前来源及其中36份共享平台投影；来源摘要、作者／许可证头及完整排版证明见[回执](verification/worktable-io-audit-20261022.json)。本批只核源码，没有调整工作台玩法。

## ALIGN-298：五工具格的直接灌液路径没有移植

原 `MultiTileEntityAdvancedCraftingTable`同时实现 `IFluidHandler`、`ITileEntityFunnelAccessible`。`fill`按16～20工具格查找可灌装的物品：单件时替换该格，多件时分出一件放入空格或可合并的已灌装格，并提供模拟／提交分支。它不需要工作台拥有普通储液罐。

原流体漏斗实际调用目标的 `funnelFill`，先模拟、再提交；工作台的此方法委托同一 `fill`。因此这不是仅保留了一个无人调用的接口，也不只是制作配方的容器返还。

当前共用实体和充能子类没有五格灌装方法，也没有实现已存在的 `FluidToolTarget`。Forge父类只发布物品能力；Neo专用注册发布两类工作台的物品能力和充能表的能源能力。现有 `FluidAttachmentBlock.attachedHandler`先问显式工具访问，再问原生流体能力；覆盖板Mixin只包装已有结果，不能补出这套五格灌装流程。

本条指默认内置消费者缺失，不断言任何外部模组都不能额外注册能力。它与ALIGN-296不同：296是制作时向相邻储罐取液补充原容器，298是把外部流体直接送进台内工具格。后续不能以新加一只普通储罐代替原格位目标，真实注入量、模拟、分堆与满格守恒还需验证。

## ALIGN-299：无限工具尖端参与时，结果合并限制不同

原 `consumeMaterials`在光标／目标堆非空时，先验证产物身份和容量，再检查九宫格是否有 `gt:autocrafterinfinite`；存在则直接返回原持有堆，不继续消耗或合并。本次追到原 `MultiItemRandomTools`的8000～8009十个机器人尖端实际注册了该标签，不是一个空标签分支。

当前十个对应尖端在生成表及两版注册循环中存在，`CraftingTools.infinite`也有实际身份判断。工作台计划会保留这种输入，菜单的结果制作则只检查产物一致与容量，没有原来针对非空结果堆的尖端门控。

限定正常左击、配方确实接受该尖端、其余原料足量、每次产出1件且最大堆叠64：

| 尖端与光标条件 | 原版允许这次制作 | 当前允许这次制作 |
| --- | --- | --- |
| 无无限尖端，光标空 | 是 | 是 |
| 有无限尖端，光标空 | 是 | 是 |
| 无无限尖端，光标已有相同产物且未满 | 是 | 是 |
| 有无限尖端，光标已有相同产物且未满 | 否 | 是 |
| 光标已满，或是其它物品 | 否 | 否 |

回执保留两种尖端资格×四种光标状态的八个源码条件；其中一个资格／状态组合不同。不是八次实际GUI测试，也不意味着任意配方都接受尖端。原批量点击也会调用同一合并门控，但本批没有按全部批量路径外推制作次数。

这是应独立决策的原版限制差异，本批不自动禁止当前尖端手工使用。它不等于物品应被消耗、普通工具应失去保护，亦不同于ALIGN-292的自动合成原料标签和ALIGN-297的手工具头材料比较。

## 已有充能、界面与重载入口

- 原充能表对五个工具格依次调用 `IItemEnergy.Utility.inject`，每格请求一包；当前在16～20格做同样的逐格请求，实际接受正数才累计，提交时才回写副本。有效自有物品返回0／1包的通常路径已接入；异常外部回调不是本批等价结论。
- 当前需求探测也在栈副本上执行，不会为了查询给原栈添加数据；正包、非空类型、服务端／移除状态与`Long.MIN_VALUE`保护保留。实体没有普通方块能源缓冲，也不对外输出能源，不能因为存量显示0就报告充能必然失效。
- 原根类的RF入口直接使用 `RF, size=1, amount=请求值`；当前FE入口也是这一路径。没有仅因该签名而登记“RF未换算EU”的错误。具体物品接受哪些能量仍由物品API决定，全部类型、负包和极值尚未实测。
- 原 `IItemEnergy.Utility`还有可选IC2物品兼容分支及晶体排除；当前直接处理自身接口。旧IC2 API不是现代两版本一定存在的接口，本批保留这项外部适配待决范围，不声称已支持，也不未经确认直接恢复旧类依赖。
- 单击／右击与两种shift结果点击入口、产物不一致即停止、目标容量检查、清格／收纳按钮在当前菜单都有代码。基础存在不等于全部点击次数、网络包与原版完全相同；299单独追到了实际门控。
- 界面有蓝图空格预览和结果／按钮提示；Forge与Neo各自的背景绘制入口保持。没有做像素比较，不将屏幕类展开算成GUI已验收。
- 预览缓存消费重载generation，服务端数据包同步事件在全量重载时递增它，单玩家同步不触发。只确认接线，尚未运行实际重载、多用户或空缓存恢复。
