## 三项确认差异

| 编号 | 原版消费者 | 当前消费者与边界 |
| --- | --- | --- |
| ALIGN-364 | BlockBaseRail.getRailMaxSpeed 要求轴向相邻轨道属于 GT 的 BlockBaseRail。 | TrackBlock.sameAxis 接受任意现代 BaseRailBlock，包括原版 RailBlock。以一条 0.5 条纹轨、两端原版同向轨道、其它邻接为空且所需区块已加载为例，原条件得到 0.4，现条件得到 0.5。其它材料轨也用这个 helper；记录的是轨道返回上限，不是最终实测矿车速度。 |
| ALIGN-365 | 上述完整直轨分支调用 doChunksNearChunkExist，半径 17。 | 当前 hasChunksAt 使用坐标 ±16。位置 `(0,64,8)` 的旧范围还要求 x 区块 −2 的三块，现范围不要求；若现九块已加载、旧额外三块未加载，额定 4 的轨道返回上限可由原 1 变为现 4。对 0.5 条纹轨，两种加载分支数值相同，不能说该半径差让所有轨道都变快。 |
| ALIGN-366 | 道路判断遮挡层时，分别排除 Material.wood、isWood 和树叶。普通木板即使不是原木，也被材质条件排除。 | 导入器把前两项都映射为 Block.wood，原生读块仅用 LOGS 标签设置它。默认橡木板属于 PLANKS 而不属于 LOGS，因此可能计入隧道遮挡层。130 个这类采样块的有限案例得到隧道模式，按旧木材语义则为普通道路。数据包或其它模组可改标签，不把结论扩大到任意安装。 |

旧加载方法和木板材质使用已校验的官方 1.7.10 JAR 与 Forge 映射核对；该工件官方来源与摘要见上一批[中心群系证据](verification/center-biomes-audit-20261022.json)。现代两端实际 LevelReader、RailBlock 与默认标签提供器分别核了字节码／源码。旧 `wood` 字段与旧类名不是按字母猜测。

366 的问题是两个不同的旧谓词被折叠，不能仅删掉代码中重复的 `!wood()` 就宣称修好。364 后续也不能单纯按 `gt6ce` 命名空间过滤，因为原版的 GT 基类可以被扩展。三项本批只记录，没有修改速度、加载或隧道行为。

## 完整布局对应及已排除的误报

从原版 generate 开始到文件末尾，连同 generateRoadX、generateRoadZ，全部 16480 个有序代码 token 在列明适配后对应当前版本。适配包括四个信标委托、两处生物清理、方块／群系／符号 helper、一个地基起点、28 个下降循环下限、28 个桥墩底部相对判断，以及八次旧 Y255 强制读入区块的写入移除。

这是“经过平台替换后的完整布局对应”，不代表被替换谓词的含义也对应；366 正是其中的反例。原构造器、enabled 与配置加载不在该方法尾部比对范围内，当前模块默认全开与 CFG 后续的用户选择保持。

隧道判定读取 `mHeight+9`，当前高度 66 时为 Y75；隧道顶位于 Y73，没有改掉该判定层。普通道路／桥梁清空采样层只会减少遮挡；两半顺序生成的有界案例没有支持“第一半把另一半改成不同模式”的猜测。GTOriginFeature 已统一读取两半区段的群系。没有据此宣称所有跨区块加载时序均已实测。

十种普通材料轨道的名字、速度和抗性声明与原注册表对应；助推配方、碰撞、完整信号和最终矿车物理不由这项声明核对证明。条纹轨已有轴向／反光位转换、禁止自动弯轨／爬坡的回调、工具切换反光位，以及对应的模型和纹理。八个模型／状态 JSON、两张纹理和两端 LOGS 扩展文件已核存在／摘要，不等于真实像素验收。
