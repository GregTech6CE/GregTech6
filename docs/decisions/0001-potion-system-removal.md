# 0001：移除 GT6 药水系统

- 状态：接受。
- 日期：2026-11-03；作者：GregTech6CE 维护者；关联任务：PR #274、[药水系统移除](parity/potion-removal.md)。
- 替代/被替代关系：无。

## 背景与约束

GT6 把药水做成了一套平行于原版药水物品的流体身份：94 条带药水标志的流体、490 行机器配方、93 行饮用条目，以及罐装、木桶、瓶筐、地牢杯和防火板条箱一整串下游联动。本端已把药水身份交给原版药水物品，流体侧没有继续维护平行体系的理由。

原版酿造表在 1.20.1 与 1.21.1 都注册在代码侧且不可枚举（1.21.1 的 `PotionBrewing` 只公开通用接口配方，`potionMixes` 私有；1.20.1 Forge 的 `BrewingRecipeRegistry.getRecipes()` 同样不含药水与容器混合）。上游 GT6 没有酿造配方图，`addBrewingRecipe` 是返回失败的存根，机器批量酿造本来就是移植端新增的便利。

已发布存档（v1.0.0–v1.0.4）含药水内容，本端没有流体迁移机制。保留 `Dragon_Breath`、24 条 `potion.*` 命名的饮料流体、通用瓶子能力与 250 mB 计量，是不能破坏的边界。

## 备选与决定

- **药水身份**：停注 94 条药水流体与 `POTION` 标志，删除 490 行药水机器配方、93 行饮用条目及其资源；药水改由原版药水物品承载。
- **机器酿造**：发酵机执行探测到的原版酿造表。新增一个可见的药水输入槽，物品输入左移，药水输出复用现有物品输出；每操作 1 瓶、16 tick、256 EU，药水配方不参与并行。隐藏槽与“加第二个普通物品槽”都被否决，因为前者无法向玩家解释第三样输入，后者会改变既有发酵行的匹配语义。
- **配方来源**：运行期探测，不手抄表；39 条 GT 特色路线通过各加载器的酿造注册接口加入。不向 addon 暴露单独的 GT 药水配方接口，addon 走原版表后由探测继承。
- **下游**：密封储罐保留软锤密封与灌取锁定，删除发酵、进度与相关 NBT；地牢夜视杯取消；瓶筐经验瓶改用水加手动绿色；毒瓶与 9 个毒性木桶停注，三明治表按物品 ID 记录、无法区分药水类型，相关条目一并移除；防火板条箱随 lootbox 移植取消。
- **存档兼容**：储罐、板条箱与杯子中的存量药水流体载入后静默清空；机器背包布局不变，药水槽使用独立 NBT 键；密封储罐的旧进度 NBT 不再读取。

## 影响、落地与验证

涉及 `core` 的流体与配方数据、`minecraft` 共享代码与两个加载器节点、以及中英文资源。机器侧只新增药水槽，不改变既有物品/流体槽的编号与存档键；流体与语言资源的清理范围见[药水系统移除](parity/potion-removal.md)附录 A–F。

验证执行：`:core:check`、1.20.1 与 1.21.1 节点编译、任务要求的产物构建。仓库没有流体/语言覆盖率门禁，机器酿造、密封储罐、瓶筐经验瓶、地牢杯、罐装/倒罐与 EMI/JEI 发酵机类别仍需游戏内回归；本次未启动游戏。

未完成事项：药水槽底纹（药水图标底图）留给人工实现；其他模组瓶子“无 GT 流体时回退水”的上游行为尚未补；原版表中的实际探测结果只在运行期确定。
