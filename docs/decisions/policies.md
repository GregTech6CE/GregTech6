# GT6CE 设计方针、架构与项目管理

本文档定义 GregTech 6 Community Edition（GT6CE）的设计方针、核心特色、三层架构、路线图优先级分级标准与社区协作规范。

## 方针

- **非侵入式**：不删除或强制替换原版及其他模组的配方、世界生成（矿脉）、方块与挖矿掉落产出，不通过加载顺序或全局事件改写他人内容；只提供比原版收益更高、体验更好的正向替代方案，跨模组交互优先通过双向标准 Tag 与可开关的兼容层实现。
- **奥卡姆剃刀**：不做无意义的内容堆砌、纯数值膨胀（“扣 0”）或架空既有产线的逃课内容。优先使用原版或联动模组本身已有的内容与机制（如直接统合 1.17+ 原版粗铁、粗铜、粗金，不再维护重复物品）。
- **自洽性**：材料、配方、能量、进度与世界生成形成严密闭环。严守“无消费端不入库”原则，每项材料与流体均需具备明确的来源与独特消费端，防止单一材料数值通吃一切；未安装联动时本体完整可玩。
- **联动附属化**：可选玩法、联动兼容与非核心边缘系统移出本体，本体只保留核心科技玩法与基础工业内容。
- **可配置**：尽可能使用细粒度的可配置项以及数据包 / KubeJS 扩展能力来提供不同的游戏体验。
- **取其精华，去其糟粕**：保留并深化 GT6 极具辨识度的核心特色（见下节【核心特色】），摒弃 GT5 式的“高电压等级叠叠乐”以及原版为追求“万物皆可按成分回炉”而导致的物品矩阵爆炸（如 9 种金属箍木桶）与工具误投坩埚融毁等负体验设定；修复上游长期 `wontfix` 的机械轴/齿轮箱顽疾与线损叠加超频逼迫玩家“凑数”的反直觉设计；弱化并默认关闭“机器淋雨即刻爆炸”（保留配置作为硬核彩蛋），数值可作合理调整，不需要完全照搬原版的特定实现和随机流行为。
- **循序渐进**：科技树、难度曲线与游玩体验贯穿始终保持平滑过渡，不在初期过度惩罚玩家（提供低效但产量可预期、可自动化的过渡配方与保底手段），而在中后期通过适当的边际效益（更高的并行、高价值副产物、湿法/火法等新处理线）驱动玩家主动升级替换旧产线，并让早期基础产线持续吃到后续新能量与新技术的升级红利，避免“一条初级产线堆数量走到通关”或“单一矿物/单台慢速机器卡死整条科技线”。
- **便利化与符合直觉**：系统设计与实现应符合现代玩家的游玩习惯和常见思考逻辑，将隐藏规则与核心运行读数内建为可见信息（EMI / Jade / GUI），不设置隐蔽的怪异行为（quirk）或无预警惩罚来为难玩家。
- **谜题设置**：从前期的轻量级多能量尝试到中后期的复杂工程谜题（如坩埚自动化温控、多能量协同控制、精确定量配料），均应靠优秀的机制设计，使玩家仅使用本体自身工具与物流就能完整解决，同时允许与 AE2 等外部模组有机结合，而非靠残缺的自动化实现逼迫玩家依赖外部模组。

## 核心特色

以下六项是 GT6 真正区别于 GT5 及其他科技模组的核心灵魂，也是判断后续一切玩法“新增 / 重做 / 迁出 / 删除”的价值锚点：

- **坩埚冶金系统**：以真实开尔文熔点、沸点与比热容为基础的开放式热力学冶金。贯穿整个模组生命周期实现**从前期手工烧制浇铸 → 中后期分场景自动化 → 末期高阶自动化工程挑战**的演进，分化出**小坩埚（单方块低热惯量、快速升降温、面向多样化小批量特种制造的精确自动化）**与**大坩埚（多方块面向钢板等大宗高速批量制造，配套解决模板替换、余温控制、模具冷却、料斗批量投料与 `KU` 协同输入痛点）**的双轨特色。
- **多能量协同系统**：摒弃单一“电能（EU）电压叠叠乐”，细分为热（HU）、冷（CU）、旋转（RU）、动能（KU）、电（EU）、磁（MU）、光/激光（LU）、量子（QU）、蒸汽（SU）等真实物理能量。因跨能种转换存在显著损耗，驱动玩家因地制宜用对应能量直接驱动产线，并在各阶段通过多能量协同完成工业合成与效率跃迁。
- **覆盖板与表面控制系统**：机器六面不仅是物料与能量接口，更是可安装输送带、泵、调节器、红石检测器与控制面板的微控制器；配合扳手与螺丝刀，在方块表面直接完成精细的 I/O 分流、配额限流与状态控制。
- **世界内实体交互**：“空间里的工坊，而非菜单里的进度条”。涵盖 `5×5` 像素掩码模具雕刻与浇铸、双槽石砧/金属砧的物理锤锻（可接自动锤）、10 种带物理指针的传感器表盘，以及无需打开 GUI 即可直接在世界中完成的投料、舀取与工具加工。
- **原生物流与存储系统**：由普通漏斗、队列漏斗、筛粉漏斗、虚空收集漏斗、流体管道、物流管道、质量存储（储物桶/量子存储器）及多方块物流核心组成的物理物流网络；既保证本体自身自动化完整自洽并做出区别于数字网络的物理特色（大宗容器直连、多原料/流体成套批次投料、USB 蓝图产线联动），又允许与 AE2 等现代数字物流网络有机结合。
- **地下避难所与地牢探索**：由 28 类功能房间（走廊、柱厅、车间、储藏室、图书馆、农场、基岩矿开采房等）程序化生成的地下工业遗迹，配合战利品板条箱、材料板条箱与锭堆，构成前期探索补给与特殊材料获取节点。

## 架构

- **API**：包含接入接口與系统运行规则，提供独立版本化管理的双平台 Addon SDK（Forge 1.20.1 / NeoForge 1.21.1）。**API 严守窄语义边界**：仅提供**添加配方、定义能级、注册换皮机器、扩展世界生成**等边界清晰的声明式契约，**移除宽定义的“行为机（Behavior Machine）”抽象**——对于具有独立复杂行为逻辑的模组特殊机器，统一交由附属模组自行编写实现，避免 API 实现成本爆炸与跨版本兼容性灾难。
- **本体**：包含核心玩法与基础内容。`core` 承载与 Minecraft 解耦的纯 Java 规则与目录定义，版本节点通过 Stonecutter 维护双平台共享运行时；对 EMI / JEI / Jade 等可选外部依赖严格执行编译期隔离与零静态引用纪律。
- **附属**：包含第三方模组联动兼容、非核心玩法与可选内容（如食物与农业烹饪、枪械弹药、3D 打印增材制造、简易航天与外星矿脉、外部模组维度世界生成、引导手册等）。

## 优先级分级

为控制工程复杂度与存档兼容风险，路线图中的所有工作项按**迫切度、实现难度、工程规模与存档兼容边界**划分为四个优先级（`P0` ~ `P3`），在各版本路线图文档中通过 HTML 注释标注并按从高到低排序：

| 级别 | 定位 | 判据（迫切度 / 难度 / 规模） | 目标阶段 |
| --- | --- | --- | --- |
| **P0** | **基线收敛与阻断级痛点修复** | **迫切度极高、难度低~中、规模小~中**：直接卡死当前游玩或并行的数值/配方缺陷（如 9x 小撮矿卡并行、`1x1` 核堆无配方）、零提示导致被误判为 Bug 的隐藏规则与暴毙设定（淋雨爆炸、穿墙辐射、核心读数缺失），以及底层单一来源收敛。 | `v1.0.x ~ v1.1.x` |
| **P1** | **API 窄化与存档基线前必做：注册减法、网络/机械底层重做与世界生成重构** | **迫切度高、难度中~高、规模中~大**：`v1.1` 的 API 窄语义收敛（移除宽定义行为机）与汉化模板化；`v1.2` 锁定长期存档兼容基线前所有破坏存档 ID 的删减与剥离（死材料清理、成品无损回炉收缩与木桶去矩阵化、养蜂移除、食物/弹药迁出、世界生成重构 #388、资源治理 #383），以及管道/能量网络重做、RU 传动轴/齿轮箱重做、#342 超频下限、#237 不吞材料。 | `v1.1.x ~ v1.2.x` |
| **P2** | **专项工业深化：坩埚冶金选矿革新与物流核心/AE2 有机结合** | **迫切度中~高、难度中、规模中~大**：在 `v1.2` 存档兼容与管网基底稳固后，分版本专注攻坚**坩埚大小双轨自动化、双轨冶金与选矿革新（`v1.3`）**以及**原生物流核心特色化重塑与 AE2 有机结合（`v1.4`）**。 | `v1.3.x ~ v1.4.x` |
| **P3** | **远期构想池（Future Ideas）：未定序产线扩展与终局探索** | **迫切度中~低、难度中~高、规模中~大**：社区与团队讨论中提出的石化/高分子/电子/激光扩展产线、规模化多方块、四维能量支柱、MESU 储能、核聚变与物理辐射屏蔽以及尚待商榷的筛选机制等，统一收入 [`future-ideas.md`](../roadmap/future-ideas.md)，**不预设实现顺序，亦不作排期或必然实现的承诺**。 | `future-ideas` |

## 项目管理

- **汇报问题**：写清问题、复现步骤、预期结果与实际结果，并附上相关日志。
- **提交建议**：描述立意、修改内容，确认提议符合设计准则。
- **PR**：说明立意、修改内容和范围、实际测试结果。
- **RFC**：重大更改需要先建立 RFC issue，公开讨论并经维护者合议后决定，通过 RFC PR 合入。
- **文档管理**：遵循项目内已有的规范，将应该记录的事项记录在规定位置。
- **行为差异**：与 GT6 的行为差异需要记录原始行为、差异、原因与影响。
- **可更改性**：方针与路线图不是固定的，社区可以通过 RFC 讨论、维护者合议后修改。
