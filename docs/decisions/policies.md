# GT6CE 设计方针、架构与项目管理

本文档定义 GregTech 6 Community Edition（GT6CE）的设计方针、核心特色、三层架构、路线图优先级标准与社区协作规范。

## 设计方针

- **非侵入式**：原则上不删除或强制替换原版及其他模组的配方、矿脉生成、方块与挖掘掉落，也不通过加载顺序或全局事件强行改写外部内容；若修改某项原版行为对整体体验确有利大于弊的收益，须具体评估并尽可能提供细粒度配置开关；跨模组交互优先通过双向标准 Tag 与可开关兼容层实现。
- **奥卡姆剃刀**：如无必要，勿增实体；优先复用原版或联动模组既有的物品、流体与机制。
- **自洽闭环**：材料、配方、能量、科技进度与世界生成须彼此咬合。严守“无消费端不入库”原则，每种材料与流体都应具备可靠来源与独特用途，避免单一材料靠数值通吃全局；未安装任何外部联动时，本体依然完整可玩。
- **联动附属化**：可选玩法、跨模组联动与非核心边缘系统剥离至独立附属，本体聚焦核心工业科技与基础生存内容。
- **高度可定制**：提供细粒度配置项、数据包、公开 API 与 KubeJS 接口，方便玩家、附属作者与整合包制作者按需定制体验。
- **取其精华，去其糟粕**：保留并深化契合 GT6 核心特色（见下节【核心特色】）的设计，果断剔除冗余、凑数或背离核心体验的设定。
- **循序渐进**：科技树与难度曲线保持平滑演进。前期提供低效但预期稳定、可自动化的过渡路径与保底手段，避免单点卡死；中后期通过更高的并行度、高价值副产物与湿法/火法新工艺驱动产线迭代，并让早期产线持续受益于新能量与新技术的反哺，杜绝“初级机器堆数量通关”或“单一矿种/慢速机器锁死全局”。
- **便利直观**：系统设计贴合现代玩家的直觉与操作习惯，将隐藏规则与关键运行参数内建为可见信息（EMI / JEI / Jade / GUI），不靠隐晦的怪异机制（Quirk）或无预警暴毙惩罚为难玩家。
- **开放式谜题**：工程谜题追求开放性与系统联动，摒弃纯走流程的机械劳动；确保玩家仅凭本体工具与物流即可自由组合出优雅解法，同时支持与 AE2 等外部模组有机协同，而非用残缺的本体自动化迫使玩家依赖外部模组。

## 核心特色

以下六项是 GT6 区别于 GT5 及其他科技模组的核心灵魂，也是裁决一切内容“新增 / 重做 / 迁出 / 删除”的价值锚点：

- **坩埚冶金系统**：基于真实开尔文熔点、沸点与比热容的开放式热力学冶金。贯穿游戏全周期，从前期手工烧制浇铸逐步演进至中后期分场景自动化，分化出**小坩埚（单方块、低热惯量、快速升降温，面向多样化小批量特种制造）**与**大坩埚（多方块，面向大宗高速批量生产）**的双轨格局。
- **多能量协同系统**：摒弃单一“电能（`EU`）电压叠叠乐”，细分为热能（`HU`）、低温能（`CU`）、蒸汽（`SU`）、旋转能（`RU`）、动能（`KU`）、电能（`EU`）、磁力能（`MU`）、光能（`LU`）、量子能（`QU`）与时间（`TU`）。跨能种转换存在显著损耗，驱动玩家因地制宜采用对应能量直驱设备，并通过多能量协同实现工艺突破与效率跃迁。
- **覆盖板与表面控制**：机器六面既是物料与能量接口，也是可安装输送带、泵、调节器、红石检测器与控制面板的模块化表面；配合扳手与螺丝刀，无需繁琐菜单即可在方块表面完成精细的 I/O 分流、定量限流与状态联锁。
- **世界内实体交互**：“空间里的工坊，而非菜单里的进度条”。涵盖 `5×5` 像素掩码模具雕刻与浇铸、双槽石头砧与各材质砧的物理锤锻（可接自动锤）、10 种带物理指针的传感器表盘，以及直接在世界中完成的投料、舀取与工具维护。
- **原生物流与存储系统**：由普通料斗、队列料斗、筛粉漏斗、虚空收集料斗、流体管道、物品管道、大宗存储（储物桶/量子存储器）及多方块物流核心构成的物理物流网；既保证纯本体自动化完整自洽、体现物理车间调度的独特质感，又支持与 AE2 等现代数字网络有机结合。
- **地下避难所与工业遗迹**：由 28 类功能房间（走廊、柱厅、车间、储藏室、图书馆、农场、基岩矿开采室等）程序化生成的地下工业遗迹，配合战利品板条箱、材料板条箱与金属锭堆，构成前期勘探补给与特殊物资获取节点。

## 三层架构

- **API 层**：定义公开接入契约与系统规则，提供独立版本化管理的双平台 Addon SDK（Forge 1.20.1 / NeoForge 1.21.1）。**API 严守窄语义边界**：仅提供**添加配方、定义能级、注册换皮机器、扩展世界生成**等语义清晰、边界可控的声明式接口；**于 `v1.1` 移除宽定义的“行为机（Behavior Machine）”抽象**——凡具备独立复杂逻辑的特殊机器，均交由附属模组自行实现，避免 API 维护成本膨胀与跨版本兼容风险。
- **本体层**：承载核心科技玩法与基础工业内容。`core` 维护与 Minecraft 解耦的纯 Java 规则与目录定义，版本节点通过 Stonecutter 共享双平台运行时；对 EMI / JEI / Jade 等可选外部依赖严格执行编译期隔离与零静态引用纪律。
- **附属层**：承载第三方联动兼容、非核心玩法与可选扩展（如食物与农业烹饪、枪械弹药、简易航天与外星矿脉、外部维度世界生成等；游戏内引导手册仍纳入本体规划）。

## 优先级分级

为控制工程复杂度与存档兼容风险，路线图中的所有工作项按**迫切度、实现难度、工程规模与存档兼容边界**划分为四个优先级（`P0` ~ `P3`），在分版本路线图中以 HTML 注释标注并按从高到低排列：

| 级别 | 定位 | 判据（迫切度 / 难度 / 规模） | 目标阶段 |
| --- | --- | --- | --- |
| **P0** | **基线收敛与阻断级痛点修复** | **迫切度极高、难度低~中、规模小~大**：底层材料/配方单一事实来源收敛、构建与资源模型瘦身、高冗余废弃系统清理，以及直接卡死生存流程或并行度的阻断级缺陷（如 `9x` 小撮粉碎矿石卡并行、`1x1` 核堆缺配方、LV 电池死锁、无预警淋雨爆炸/穿墙辐射、核心读数缺失）。 | `v1.0 ~ v1.1` |
| **P1** | **API 窄化、边缘剥离、世界生成与网络重构** | **迫切度高、难度中~高、规模中~大**：`v1.1` 完成 API 窄语义收敛、汉化动态模板化、容器动态分层合图、边缘系统剥离与 ID 收口（养蜂移除、食物/弹药迁出、木桶去矩阵化、复杂成品回炉收缩）及世界生成重构（#388）；`v1.2` 集中完成管网/电网重构、RU 传动轴/齿轮箱重做、#342 超频下限、#237 防吞材料及前期研磨机与工具重做。 | `v1.1 ~ v1.2` |
| **P2** | **专项工业深化：坩埚冶金选矿革新与原生物流重塑** | **迫切度中~高、难度中、规模中~大**：在底层网络与核心机制稳固后，分版本攻坚**坩埚大小双轨自动化、焙烧—湿法双轨冶金与选矿革新（`v1.3`）**，以及**原生物流核心重塑与 AE2 有机协同（`v1.4`）**。 | `v1.3 ~ v1.4` |
| **P3** | **远期构想池：未定序产线扩展与终局探索** | **迫切度中~低、难度中~高、规模中~大**：石化脱硫裂解、合成气、工程高分子、覆铜湿法蚀刻电子链、分波段宝石激光、规模化多方块、四维能量支柱、MESU 巨型储能、核聚变与物理辐射屏蔽、高版本原版机制融入等中远期构想，统一收入 [`future-ideas.md`](../roadmap/future-ideas.md)，**不预设实现顺序，亦不承诺排期或 `v2.0` 大版本**。 | `远期构想池` |

## 项目管理与协作

- **问题反馈（Issue）**：写明问题描述、复现步骤、预期结果与实际结果，并附上版本信息与相关日志/截图。
- **功能建议**：阐述设计立意与具体改动内容，确认提案契合上述设计方针。
- **拉取请求（PR）**：说明改动背景、修改范围与双平台实际验证结果。
- **重大提案（RFC）**：涉及核心机制、公开契约或大范围内容增删的重大变更，须先建立 RFC Issue 公开讨论，经维护者合议通过后以 RFC PR 合入。
- **文档同步**：遵循仓库文档规范，在对应专题目录如实记录架构、契约与行为变更。
- **原版差异登记**：有意偏离原版 GT6 的行为须在 [与原版的特性差异](parity/README.md) 中记录原始行为、当前差异、原因与影响。
- **演进机制**：设计方针与路线图并非一成不变，社区可通过 RFC 讨论并经维护者合议后修订。
