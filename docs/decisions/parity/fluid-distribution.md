# 流体管道分布模式

`fluid.distribution` 选择同一流体组件内部的分配方式，默认 `LOCAL`。`BALANCED` 与 `SHARED` 都是本移植新增、改变玩法的模式，默认关闭；`LOCAL` 与原版 GT6 的六邻居本地扩散一致。

| 值 | 行为 | 与原版 GT6 的关系 |
| --- | --- | --- |
| `LOCAL` | 每 tick 六邻居本地扩散；`distributionLevel` 与 `pressureShare` | 一致 |
| `BALANCED` | 每 10 tick 按组件、按流体把管道液位拉平，逐边整数移动 | 新行为，默认关闭 |
| `SHARED` | 同一组件内同一流体的管道 tank 作为派生共享池，端点 fill/drain 作用于整池 | 新行为，默认关闭 |

`performance.fluid_idle_scheduling`（默认开）只跳过完全空闲管道的 `serverTick`，不改变 `LOCAL` 的分配数学、节拍或吞吐；关闭后恢复每根已加载管道每 tick 执行一次，用于对照和排障。

## BALANCED

- **触发**：组件内有流体时，每 10 tick 由该组件中实际 tick 的一根管道发起一次 pass；空组件休眠，不扫描。
- **分组**：按流体身份。过滤器、快门，以及在任一方向被挡住的泵边都视为切割；压力阀、排水、通风覆盖板的宿主管道整根排除，避免覆盖板动作时点随均衡漂移。
- **移动**：逐边、整数、`min(盈余, 亏空)` 分配，死区 1 个单位；不瞬移。总容量不足时，多余量留在原管道，下一 pass 继续。
- **压力**：该模式下 `pressureShare` 不参与；每 tick 的管道间 `distributionLevel` 分配由均衡 pass 取代。机器与炼药锅的每 tick 端点填充保留，`distributionLevel` 的计算仍计入相邻管道。
- **覆盖板**：过滤器/快门逐边检查，泵方向不被绕过；压力阀、排水、通风的宿主管道不参与均衡。
- **区块**：只跨已加载区块；未加载边界视为切割。
- **守恒**：只做整数移动，余数按确定的组件顺序保留在原管道，不产生或丢失流体。

`BALANCED` 的偏离仅限“管道之间如何分配”，端点填充、危害/温度、覆盖板 tick 和 NBT 格式不变。

## SHARED

- **存储**：每根管的 tank 仍是唯一存储，池是组件快照上的派生视图；存档/NBT 不变，拆分时各管保留自己的量，不需要重新分配。
- **端点操作**：面访问仍先检查连接、`allowsFluid` 与 `coverFluidFilterPermits`；通过后 fill/drain 会遍历组件，按确定顺序在管道之间分配。无面/内部访问走同一池。
- **覆盖板**：池遍历不经过面，因此内部管道之间的移动不检查内部覆盖板（过滤器/快门/泵）。这是与 `LOCAL` 最大的语义差异。
- **本地扩散保留**：每 tick 的 `distributeChannel` 在 SHARED 下仍按 `LOCAL` 运行（管道间扩散、`pressureShare`、机器/炼药锅推送），并继续按覆盖板方向放行；这是环境的物理搬运路径。池只扩大端点 fill/drain 的可见范围；池内部移动不经过面，因此不检查内部覆盖板。保留本地扩散是为了不让“机器只靠相邻管道 push”这条既有行为在多段组件里断流。
- **压力阀**：其宿主管道被排除出池（该管自身的面操作回退为本地读写），避免整池语义与 `tanks[0]` 动作冲突。
- **温度/危害**：逐管保留与判定，不做池内平均；不同温度的同一流体按所在管道各自处理。
- **压力**：`pressureShare` 不参与，与 `BALANCED` 相同。
- **区块**：池只在已加载区块内有效；未加载边界视为切割。
- **模式切换**：`LOCAL ↔ BALANCED ↔ SHARED` 只影响运行期分配，不迁移或改写 tank NBT。切换时正在传输的量留在各管，守恒。
